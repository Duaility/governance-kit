# Configuration

Directives declare typed defaults and docs in `directive.yaml`; the repo may override only settings the author marks tunable. Nothing is configured by editing check code.

## The two layers

| Layer | File | Owner | When it changes |
|---|---|---|---|
| **Registry** | `<directive>/directive.yaml` `config:` | The pack author | Refreshed on `governance pack update` |
| **Overlay** | `.governance/conf/<owner>/<pack>/<directive-id>.conf` | You | Hand-edited, committed like any file |

Each config entry declares `name`, `type`, `doc`, `default`, and `tunable`. The overlay is seeded from a generic stub when config exists and is yours from then on—pack updates never touch it.

Checks use shared helpers (`conf_get` for scalars, `conf_list` for lists). A tunable overlay wins; fixed entries always use the manifest default. Environment variables are not a config tier.

```
.governance/conf/
└── governance-kit/
    ├── foundation/
    │   └── internal-doc-links.conf     # reachability roots (opt-in)
    └── audit/
        └── doc-integrity.conf          # extra frozen-file / append-only rules
```

## Common knobs

- **Opt-in doc lists** — `internal-doc-links`' `reachable` sub-check is a no-op until you declare roots in its overlay.
- **Rule lists** — `doc-integrity` ships standard rules in its manifest; its tunable overlay adds repo-specific rules.
- **Add / drop semantics** — list-valued overlays use `KEY+=<item>` and `KEY-=<item>`. Bare additions and `!<item>` removals remain shorthand when a directive declares only one list key.
- **Tunable limits** — metric thresholds such as `repo-hygiene`'s file-size and source-length limits are scalar config entries overridden with `KEY=value` rows.

## Presets are configuration too

Which directives install at all is declared per pack in `pack.yaml` presets (`minimal` / `standard` / `strict`), chosen at `governance init` and adjustable later with `directive add` / `directive remove`. See [Quickstart — choosing a preset](/guide/quickstart#choosing-a-preset) and [Packs](/concepts/packs#presets).

## What not to configure by hand

The lockfile, `CONSTITUTION.md`, and anything carrying the `# governance-kit:managed` marker are written only by the verbs. Overlays under `.governance/conf/` are the deliberate exception — they are *designed* to be hand-edited and committed.

<Note>
Each directive's exact knobs, defaults, and tunability are documented in its `directive.yaml` config registry. The [directive catalog](/reference/directive-catalog) lists configurable directives.
</Note>
