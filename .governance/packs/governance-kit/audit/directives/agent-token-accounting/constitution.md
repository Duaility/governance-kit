### agent-token-accounting

- **Directive**: Every non-merge, non-revert commit carries the full trailer set (`Agent`, `Issue`, `Session`, `Token-Input`, `Token-Output`, `Token-Total`, `Cost-Key`, `Cost-USD`), satisfies `Token-Total = Token-Input + Token-Output`, and has exactly one matching row under `## Accounting` → `### Costs` in the issue's receipt (`receipts/issue-<N>.md`) whose numbers agree with the trailers (`Token-Input == row.input + row.cache_create`, `Token-Output == row.output`, `Token-Total == row.new_work`, `Cost-USD == row.cost_usd`). Cost rows are well-formed — 12 columns (`cost-key | agent | session | issue | model | input | cache-create | cache-read | output | new-work | cost-usd | note`) with `new-work == input + cache_create + output` (cache_read is tracked but deliberately excluded from new-work) and `cost-usd` a non-negative float on every row that names a model — each row's `issue` matches its receipt's issue, and `Cost-Key` is globally unique across `receipts/*.md`. `Cost-Key` is opaque (`<agent>-<session-short>-<epoch>-<n>`, where `<n>` is a per-(prefix) counter that closes the same-second collision window) — a join token between the receipt row and the commit trailer, not a parseable structure.
- **Rationale**: A repo that opts into agent-governance is committing to "every change to the tree is produced through an agent runtime", so an untrailered commit is a bug, not an allowed mode. Mandatory trailers turn the per-issue receipt into the single system-of-record for agent cost and provenance. Token trailers give branch-time provenance reviewers can read; the receipt's Accounting section is the durable ledger that survives squash merges. Homing rows in `receipts/issue-<N>.md` rather than a central `COSTS.md` (issue #201) exploits invariants the repo already enforces — one issue → one PR → one receipt, frozen on the trunk by doc-integrity — to make the accounting write target conflict-free (only the issue's own PR branch writes it) and bounded (the file scales with one issue's commits, not the whole history). The central ledger had neither property: it grew without bound and any two in-flight PRs collided on its tail. Splitting cache traffic into its own columns keeps the ledger lossless; `new-work` deliberately excludes `cache_read` so the token headline represents new work, not cache rent. The `cost-usd` column (computed from the sibling `lib/rates.py`, whose built-in rate table a repo can extend or override with `rate <model> ...` rows in `.governance/conf/governance-kit/audit/agent-token-accounting.conf`) is the only single-number headline that compares across commits with different cache mixes, and the family-prefix fallback in the rate table means a new minor model release resolves to its family's schedule rather than dropping a blank — so every priced row has a cost and a truly unpriced model is a bug that blocks the commit, not a silent skip. Cross-issue queries are served by a read-only aggregation script (`lib/report.py`) over `receipts/*.md`, so nobody is tempted to bring a central ledger back just to run a sum.
- **Enforced by**: `.governance/packs/governance-kit/audit/directives/agent-token-accounting/check.sh`, plus sibling helpers in the agent-token-accounting directive folder — `hooks/pre-commit.sh` resolves the issue's receipt and writes the matching cost row (using `runtimes/<runtime>.sh` to read the agent's transcript and `lib/receipt_io.py` to splice it into the `### Costs` sub-table, creating the receipt if absent), and `hooks/prepare-commit-msg.sh` stamps matching trailers from the pre-commit handoff. The bootstrap hook generator wires all three into `.githooks/pre-commit`, `.githooks/commit-msg`, and `.githooks/prepare-commit-msg` respectively. **Per-block validation**: `lib/trailers.py` splits the commit body into trailer-only paragraphs and cross-checks every (block, receipt row) pair anchored by `Cost-Key` — because cost-keys are globally unique it parses all receipts into one `cost-key → row` map and anchors each block regardless of which receipt holds it. On a squash-merge body the trailer set repeats once per folded sub-commit, and each (Cost-Key, Token-*, Cost-USD) tuple must round-trip with its own receipt row — global last-wins parsing would keep only the trailing block's trailers and leave every other sub-commit's row silently unverified.
- **Exceptions**: Merge commits and revert commits are exempt (merges detected via `git log --format=%P` showing >1 parent, reverts via subject starting with `Revert "`). One opt-in commit-body waiver bypasses the trailer + receipt check: `governance: allow-agent-token-accounting unsupported-runtime: <reason>`, accepted on any commit where the active agent runtime has no `runtimes/<name>.sh` adapter. The reason must be non-empty; it sits in the commit body as the audit trail for the gap (no receipt row is written for waivered commits — discover them via `git log --grep='allow-agent-token-accounting'`, not via a receipt scan). The install commit is **not** exempted by check.sh — `governance init` is responsible for making the install commit pass on the first try (validator dry-run + inline fix + normal `git commit`); no bootstrap accommodation lives in this directive. **Mode B on `main` actively validates HEAD's trailer blocks** even when the merge-base walk finds no new work (`base..HEAD` empty) — squash-merge commits land on `main` via GitHub's server and bypass the local commit-msg hook, so without this single-commit fallback their per-Cost-Key blocks would go unchecked. The HEAD fallback is the kit-side counterpart to the unsupported-runtime waiver: malformed squash commits fail loudly in CI on `main`; legitimate gaps opt out via the waiver token.

> **Installation note.** The directive folder is self-contained — `lib/` (ledger, trailers, rates, receipt_io, report), `hooks/` (pre-commit side effects, prepare-commit-msg stamping), and `runtimes/` (per-runtime transcript readers) all live inside the directive folder and are installed as a unit. The directive ships no central ledger asset — receipts are created on demand by the hook. See this directive's `README.md` for runtime wiring.
