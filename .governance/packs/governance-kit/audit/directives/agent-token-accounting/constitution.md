### agent-token-accounting

- **Directive**: Every agent-authored commit's token cost is recorded as exactly one row under `## Accounting` → `### Costs` in the issue's receipt (`receipts/issue-<N>.md`), and the receipt's recorded cumulative never silently falls behind the transcript. **Endpoint reconciliation** (commit time): when an agent runtime is detected, the session's cumulative token counters are read from the transcript and the receipt's recorded `cum-*` for that session must equal them — a ledger that lags the transcript is the signature of a commit whose cost row was never written. Cost rows are well-formed — v4 is 16 columns (`cost-key | agent | session | issue | model | input | cache-create | cache-read | output | new-work | cost-usd | cum-input | cum-cache-create | cum-cache-read | cum-output | note`). The four `cum-*` columns are the row's **absolute transcript coordinates** — the session's cumulative input / cache-create / cache-read / output counters at this commit, written blind from the transcript — and are the accounting source of truth; the delta columns (`input`/`cache-create`/`cache-read`/`output`/`new-work`/`cost-usd`) are **derived claims** for display. `new-work == input + cache_create + output` (cache_read is tracked but deliberately excluded from new-work), `cost-usd` is a non-negative float on every row that names a model, each `cum-*` is a non-negative integer no smaller than its own delta, each row's `issue` matches its receipt's issue, and `cost-key` is globally unique across `receipts/*.md`. Per session: the cumulative columns are **monotonic** (a counter that goes backwards is a violation), and where a session's consecutive rows are co-visible the validator **reconciles** each derived delta against the cumulatives — `delta == cum(n) − cum(n−1)` against the true predecessor (the co-visible row with the greatest cumulative below this one); where that predecessor isn't in the tree the pair is skipped, never blocked. `cost-key` is opaque (`<agent>-<session-short>-<epoch>-<n>`, where `<n>` is a per-(prefix) counter that closes the same-second collision window) — a join token, not a parseable structure.
- **Rationale**: A repo that opts into agent-governance is committing to "every change to the tree is produced through an agent runtime", so an unaccounted commit is a bug, not an allowed mode. **Why no commit trailers (issue #293)**: the directive used to stamp the cost onto the commit as trailers (`Agent`/`Issue`/`Session`/`Token-*`/`Cost-Key`/`Cost-USD`) and cross-check the stamped copy against the receipt row. But the trailer was a *denormalised projection* of the row — every value it carried was a strict subset of the row — kept honest by a bidirectional cross-check whose only consumer was the cross-check itself, plus a per-directive Mode-B HEAD-fallback to re-validate the copy after a server-side squash discarded the source commits. The receipt is already the durable, doc-integrity-frozen ledger (`ledgers over transcripts`); completeness is better proven by **reading the source directly** than by stamping and re-verifying a copy. Because rows store *absolute* cumulative coordinates, the endpoint check (receipt `cum-*` == transcript `cum-*`) catches exactly the silent-no-row failure the mandatory `Agent:` trailer used to catch — and it needs no squash gymnastics, since it runs at commit time against the live transcript, not against the commit message. The cost the design accepts: per-commit attribution for a commit made via `--no-verify` (no transcript in CI to reconcile against) is no longer recoverable; but the absolute coordinates preserve session-*total* fidelity — a missing intermediate commit's tokens roll into the next accounted row, and double-counting stays structurally impossible to write and provable to detect. Homing rows in `receipts/issue-<N>.md` rather than a central `COSTS.md` (issue #201) makes the write target conflict-free (only the issue's own PR branch writes it) and bounded. **Event-sourcing the ledger (issue #229)**: a session that spans branches used to double-count a blocker's tokens into the next commit because the write path derived the delta from *visible* rows; the absolute `cum-*` coordinates remove that dependency — a row claims a position on a monotonic counter, not a quantity, so the write path reads only a per-session checkpoint (never the receipts). The delta columns stay as self-contained, human-readable claims so a receipt reads in isolation. `cost-usd` (from sibling `lib/rates.py`, extensible via `rate <model> ...` rows in `.governance/conf/governance-kit/audit/agent-token-accounting.conf`) is the single headline that compares across commits with different cache mixes; the family-prefix fallback means a new minor model resolves to its family's schedule rather than dropping a blank, so a truly unpriced model blocks the commit at write time. Cross-issue queries are served by a read-only aggregation script (`lib/report.py`) over `receipts/*.md`.
- **Enforced by**: `.governance/packs/governance-kit/audit/directives/agent-token-accounting/check.sh`, plus sibling helpers in the directive folder. `hooks/pre-commit.sh` resolves the issue's receipt and writes the matching cost row, reading the session's prior cumulative from a git-dir checkpoint (`governance-token-checkpoints.json`) to derive the delta (never from the receipts), then advancing the checkpoint; runtime detection + the transcript cumulative come from `lib/runtime.sh` (shared with `check.sh`), which dispatches to `runtimes/<runtime>.sh`. The bootstrap hook generator wires `pre-commit.sh` into `.githooks/pre-commit` and `check.sh` into `.githooks/commit-msg`. Row I/O lives in `lib/ledger.py`, receipt validation (shape + global cost-key uniqueness) in `lib/validate.py`, and cumulative reconciliation / monotonicity / checkpoint in `lib/reconcile.py` — `validate-dir` runs all three in both Mode A (commit-msg) and Mode B (CI). **Endpoint reconciliation runs in Mode A only**: it re-derives the transcript cumulative via `lib/runtime.sh` and compares it to the receipt's recorded `cum-*` (`ledger.py session-cum`). It is commit-time-only by design — running it off the commit path (e.g. a mid-session `run.sh`) would false-fail because the transcript legitimately leads the not-yet-committed work.
- **Exceptions**: Revert commits are exempt (subject starts with `Revert "`); merge commits never reach the commit-msg hook. A commit authored outside a recognised agent runtime is a no-op for the endpoint check (no transcript, no cost to account) — release commits and human commits pass without a waiver. One opt-in commit-body waiver bypasses the endpoint check: `governance: allow-agent-token-accounting <reason>` (reason required), for the rare legitimate out-of-hook commit or a reconciliation mismatch on a genuinely unrecoverable predecessor; discover them via `git log --grep='allow-agent-token-accounting'`. Legacy v1/v2/v3 rows (8/10/12 columns, no `cum-*`) keep parsing and are validated to their own rules — excluded from cumulative reconciliation and monotonicity, so no historical receipt needs backfilling. The install commit is **not** exempted — `governance init` makes it pass on the first try (validator dry-run + inline fix + normal `git commit`).

> **Installation note.** The directive folder is self-contained — `lib/` (ledger, validate, reconcile, rates, receipt_io, report, runtime), `hooks/pre-commit.sh` (the side-effect writer), and `runtimes/` (per-runtime transcript readers) install as a unit. There is no `prepare-commit-msg` hook (issue #293 retired the trailers) and no central ledger asset — receipts are created on demand by the hook. See this directive's `README.md` for runtime wiring.
