### consumed-tree-integrity

- **Directive**: (Repo-local dogfood directive.) The vendored consumed tree under `.governance/packs/` must be an honest materialization of the pins recorded in `.governance/packs.lock`. For every `source: gh` pack entry: the pinned `sha` must be a real commit in this repo's history, the ref's `@<rev>` must be a real tag that resolves to that exact `sha`, the claimed `subpath/pack.yaml` must exist at the `sha`, and every vendored directive folder must byte-match what the product's `copy_tree_without_evals` materializes from the pin (the directive subtree at the `sha`, minus the `evals/` and `install-assets/` subfolders). For `source: local` packs the vendored directive set must equal the lock's directive list. Every pack folder under `.governance/packs/` must have a lock entry.
- **Rationale**: This repo dogfoods its own product, so `.governance/` is meant to be exactly what `governance install` produces for a consumer pinned at released tags — a *true specimen*, not a hand-approximation. Before this directive (issue #200) the lock pinned a fictional `sha` (a commit predating the namespace redesign, at which the concern-pack paths did not exist), and the hand-synced consumed tree had silently drifted 24 files behind `packs/` — the dogfood was enforcing an older version of its own rules than it shipped, and nothing guarded the drift. A trust tool whose own lock file lies is self-refuting. This directive makes that fiction mechanically impossible to commit: a stale pin fails the sha/tag/path assertions, and a hand-edit of the consumed tree fails the byte-match. The repair path is never a hand-edit — it is `governance pack update`, run in a post-release PR, which re-pins the lock and regenerates the tree from the new tags. (The dogfood pins point at `gh:duaility/governance-kit`, this same repo, so every pinned commit is available offline — the check needs no network in the hook or in CI.)
- **Enforced by**: `.governance/packs/duaility/governance-kit/directives/consumed-tree-integrity/check.sh` (repo-state; CI/run.sh) and `.githooks/pre-commit`.
- **Exceptions**: None. If the consumed tree is wrong, re-pin and re-materialize via `governance pack update` against real release tags — do not hand-edit `.governance/packs/` or the lock. See `kit/references/PACK_VERBS.md` and the two-lane dogfood model in `AGENTS.md`.
