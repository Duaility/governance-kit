### no-commit-path-python

- **Directive**: (Repo-local dogfood directive.) No tracked file governance-kit authors for the consumer commit path invokes `python` or `python3` — not in a shebang, and not as a command anywhere in the body. The scanned set is the *source* commit path: `kit/assets/dot-governance/lib.sh`, `kit/assets/dot-governance/run.sh`, `kit/assets/dot-governance/runtimes/*.sh`, every pack directive's `check.sh` / `hooks/*.sh` / `runtimes/*.sh` under `packs/*/directives/*/`, and this repo's own `.githooks/*` dispatchers. Detection is command-position, not word-match: the token must sit at the start of a shell command (line start, or after `;` `&` `|` `(` `$(`, with an optional leading shell keyword), so the word `python` inside prose or inside a hyphenated identifier is not a violation.
- **Rationale**: Issue #355 locks the product's dependency posture — a consumer repo needs nothing but bash + git to commit — and Q11 of that issue is explicit that *the kit should hold itself to it as a directive*. A `python3` call sitting on the hook every commit runs through means a consumer without `python3` on `PATH` gets a broken hook the first time they clone the repo, silently, with no signal until the pre-commit dispatcher errors out. The promise belongs to the repo that authors that path for everyone else, so it is enforced here against `kit/` and `packs/`, not shipped as a rule a consumer must run against a `.governance/` tree it did not write and cannot fix. Two lanes are exempt by the same issue's lane table and are deliberately out of scope: the scheduled sweep engine (`kit/assets/dot-governance/sweep.py`) and the lifecycle verbs (`kit/assets/packs/lib/**`), which are governed instead by the sibling `stdlib-only-python`. This repo's own `.governance/` tree is also out of scope — it is vendored from the *last release* and lags `packs/` / `kit/` by one cycle by design.
- **Enforced by**: `.governance/packs/duaility/governance-kit/directives/no-commit-path-python/check.sh` (repo-state; CI/run.sh) and `.githooks/pre-commit`.
- **Exceptions**: Path-glob waivers live in the sibling `defaults.conf` (empty by default — the directive is absolute out of the box) layered with the overlay `.governance/conf/duaility/governance-kit/no-commit-path-python.conf` — a bare line exempts a path from the scan, `!<path-glob>` un-exempts one of the shipped defaults. Reach for a waiver only to record a knowingly-accepted external constraint, never to launder a new violation: on this path the correct fix is always to rewrite the step in bash + POSIX awk.
