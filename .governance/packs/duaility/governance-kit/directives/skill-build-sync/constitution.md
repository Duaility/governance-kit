### skill-build-sync

- **Directive**: (Repo-local dogfood directive.) The committed published-skill tree `skill/` must be byte-identical to what `scripts/build-skill.sh` derives from `governance/`: `skill/assets/**` (the vendored engine lib and `kit.yaml` version anchor) is regenerated by the script and compared; `skill/SKILL.md` is hand-authored source and exempt. The repair path is `bash scripts/build-skill.sh`.
- **Rationale**: `npx skills` installs the entire `skill/` directory verbatim — it is the only artifact users' machines receive. Its engine lib is a derived copy of `governance/assets/packs/lib/`; without a drift check, an edit to the kit sources that skips the rebuild (or a hand-edit to the vendored copy) would silently ship stale or divergent bootstrap code, the exact skew the thin-shim split (issue #198) exists to prevent.
- **Enforced by**: `.governance/packs/duaility/governance-kit/directives/skill-build-sync/check.sh` (repo-state; CI/run.sh) and `.githooks/pre-commit`.
- **Exceptions**: None. `scripts/release.sh` re-runs the build as part of every kit release, so release commits are always in sync by construction.
