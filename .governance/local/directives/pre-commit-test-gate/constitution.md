### pre-commit-test-gate

- **Directive**: In this source repository, the tracked `.githooks/pre-commit` dispatcher must invoke the kit-internal test umbrella (`scripts/test.sh`) whenever it exists. The umbrella must in turn fan out to every product-code test layer: `scripts/test-packctl.py` (preset / CLI), `scripts/test-packctl-validate.py` (`validate_pack_dir` matrix), `scripts/test-packverb.py` (refs / capability glob / lockfile), `scripts/test-install-sh.sh` (manifest writer matrix + install helpers), `scripts/test-hooks-sh.sh` (dispatcher generation), `scripts/test-runtime.sh` (shipped `dot-governance/run.sh` + `lib.sh`), and `scripts/test-packs.sh` (pack smoke + evals).
- **Rationale**: governance-kit is itself governance tooling. A commit that changes pack helpers, hook generators, the manifest writer, the runtime files we ship to consumers, or any of the Python lifecycle code must not be able to bypass kit-internal tests locally. Routing every test layer through one umbrella keeps the pre-commit gate, the directive that enforces it, and the CI workflow agreeing on a single entrypoint.
- **Enforced by**: `.governance/local/directives/pre-commit-test-gate/check.sh`
- **Exceptions**: Emergency commits may use the standard hook escape hatches (`SKIP_GOVERNANCE=1 git commit ...` or `git commit --no-verify`), but CI still runs `scripts/test.sh`.
