### agent-token-accounting

- **Directive**: Every agent-authored commit's token usage is recorded as exactly one row under `## Accounting` → `### Costs` in the issue's receipt (`receipts/issue-<N>.md`), and the staged receipt row must match the token endpoint frozen by the pre-commit writer for that exact staged tree. **Endpoint reconciliation** (commit time): when an agent runtime is detected, `check.sh <msg-file>` recomputes `git write-tree`, reads `.git/governance-token-endpoints/<tree>.endpoint`, and verifies that the endpoint's `cost_key`, `session`, and `cum-*` coordinate match the staged receipt row. A missing endpoint is a violation because the runtime-aware pre-commit hook did not run; a mismatched endpoint is a violation because the row does not record the coordinate the writer sampled. Later transcript movement is charged to a later row, not to the already-frozen commit attempt. Cost rows are well-formed — v5 is 17 columns (`cost-key | agent | session | issue | model | input | cache-create | cache-read | output | new-work | cost-usd | cum-input | cum-cache-create | cum-cache-read | cum-output | source | note`). The four `cum-*` columns are the row's **absolute session coordinates** — the runtime's cumulative input / cache-create / cache-read / output counters at this commit, written blind from what the runtime reported — and are the accounting source of truth; the delta columns (`input`/`cache-create`/`cache-read`/`output`/`new-work`) are **derived claims** for display. `source` names the runtime adapter that produced the row (`claude-code`, `codex`, `manual`). `cost-usd` is **the figure the harness itself reported, copied verbatim, and empty when the harness reported none** — it is validated only as empty-or-non-negative-decimal, because the kit owns no rate card and computes no price. `new-work == input + cache_create + output` (cache_read is tracked but deliberately excluded from new-work), each `cum-*` is a non-negative integer no smaller than its own delta, each row's `issue` matches its receipt's issue, and `cost-key` is globally unique across `receipts/*.md`. Per session: the cumulative columns are **monotonic** (a counter that goes backwards is a violation), and where a session's consecutive rows are co-visible the validator **reconciles** each derived delta against the cumulatives — `delta == cum(n) − cum(n−1)` against the true predecessor (the co-visible row with the greatest cumulative below this one); where that predecessor isn't in the tree the pair is skipped, never blocked. `cost-key` is opaque (`<agent>-<session-short>-<epoch>-<n>`, where `<n>` is a per-(prefix) counter that closes the same-second collision window) — a join token, not a parseable structure.
- **Rationale**: A repo that opts into agent-governance is committing to "every change to the tree is produced through an agent runtime", so an unaccounted commit is a bug, not an allowed mode. **Why no commit trailers (issue #293)**: the directive used to stamp the cost onto the commit as trailers and cross-check the stamped copy against the receipt row, but the trailer was a *denormalised projection* of the row, kept honest by a bidirectional cross-check whose only consumer was the cross-check itself. The receipt is already the durable, doc-integrity-frozen ledger (`ledgers over transcripts`); completeness is better proven by freezing the pre-commit writer's sampled endpoint and verifying the staged row against it. Because rows store *absolute* cumulative coordinates, the endpoint check catches the silent-no-row failure the mandatory `Agent:` trailer used to catch — and keying the endpoint by the staged tree (issue #305) makes the check stable even when the transcript advances between pre-commit and commit-msg. The cost the design accepts: per-commit attribution for a commit made via `--no-verify` is no longer recoverable; but the absolute coordinates preserve session-*total* fidelity — a missing intermediate commit's tokens roll into the next accounted row, and double-counting stays structurally impossible to write and provable to detect. Homing rows in `receipts/issue-<N>.md` rather than a central `COSTS.md` (issue #201) makes the write target conflict-free and bounded. **Event-sourcing the ledger (issue #229)**: a session that spans branches used to double-count a blocker's tokens into the next commit because the write path derived the delta from *visible* rows; the absolute `cum-*` coordinates remove that dependency — a row claims a position on a monotonic counter, not a quantity, so the write path reads only a per-session checkpoint. **Why the kit stopped pricing (issue #355)**: up to v4 the directive shipped a hand-maintained rate card (`lib/rates.py` plus `rate <model> …` conf rows) and multiplied it against the transcript to fill `cost-usd`. Every number in it was a guess about someone else's billing — stale the day a vendor moved a price, wrong for negotiated rates, blind to per-account discounts — and a model with no row *blocked the commit*. Worse, the guess was rendered to four decimal places, which reads like a measurement. v5 inverts the source of truth: the runtime adapter reports the harness's own figure or nothing at all, the kit copies it verbatim into the row alongside the `source` that produced it, and a blank cell is the honest record of "this harness does not report dollars". Nothing about pricing can block a commit any more, because nothing in the directive prices. The same rewrite took the whole commit path off python (bash + POSIX awk only), so a consumer needs nothing but bash and git to commit. Cross-issue queries are served by a read-only aggregation script (`lib/report.py`) over `receipts/*.md`, which is invoked by humans and never by a hook.
- **Enforced by**: `.governance/packs/governance-kit/audit/directives/agent-token-accounting/check.sh`, plus sibling helpers in the directive folder — all bash + POSIX awk. `hooks/pre-commit.sh` resolves the issue's receipt and writes the matching cost row, reading the session's prior cumulative from a git-dir checkpoint (`governance-token-checkpoints/<session>`) to derive the delta (never from the receipts), stages the receipt, writes the frozen endpoint under `governance-token-endpoints/<tree>.endpoint`, then advances the checkpoint; runtime detection and the harness-reported usage come from `lib/runtime.sh`, which dispatches the `cost` verb to `runtimes/<runtime>.sh`. The bootstrap hook generator wires `pre-commit.sh` into `.githooks/pre-commit` and `check.sh` into `.githooks/commit-msg`. Markdown/table plumbing lives in `lib/receipt.sh`, the row schema and append in `lib/costs.sh`, receipt validation (shape + global cost-key uniqueness + reconciliation + monotonicity) in `lib/validate.sh`, and endpoint/checkpoint I/O in `lib/endpoint.sh` — `costs_validate_dir` runs the receipt checks in both Mode A (commit-msg) and Mode B (CI). **Endpoint reconciliation runs in Mode A only**: it is commit-time-only by design — running it off the commit path (e.g. a mid-session `run.sh`) would false-fail because no staged-tree endpoint is expected there.
- **Exceptions**: Revert commits are exempt (subject starts with `Revert "`); merge commits never reach the commit-msg hook. A commit authored outside a recognised agent runtime is a no-op for the endpoint check (no runtime, no usage to account) — release commits and human commits pass without a waiver. One opt-in commit-body waiver bypasses the endpoint check: `governance: allow-agent-token-accounting <reason>` (reason required), for the rare legitimate out-of-hook commit or a reconciliation mismatch on a genuinely unrecoverable predecessor; discover them via `git log --grep='allow-agent-token-accounting'`. Legacy v4 (16 columns, no `source`) and v3 (12 columns, no `cum-*`) rows keep parsing and are validated to their own rules — v3 rows are excluded from cumulative reconciliation and monotonicity, and both legacy shapes keep the pre-v5 rule that a row naming a model carries a price, so no historical receipt needs backfilling. The install commit is **not** exempted — `governance init` makes it pass on the first try (validator dry-run + inline fix + normal `git commit`).

> **Installation note.** The directive folder is self-contained — `lib/` (receipt, costs, validate, endpoint, runtime, plus the off-commit-path `report.py`), `hooks/pre-commit.sh` (the side-effect writer), and `runtimes/` (per-harness adapters) install as a unit. Only `report.py` is python, and nothing on the commit path calls it. There is no `prepare-commit-msg` hook (issue #293 retired the trailers), no rate card (issue #355 retired pricing), and no central ledger asset — receipts are created on demand by the hook. See this directive's `README.md` for runtime wiring.
