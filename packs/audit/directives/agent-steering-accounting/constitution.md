### agent-steering-accounting

- **Directive**: Each detected human-steering event (an interrupt, or a classifier-confirmed correction) on a branch is recorded as a row under `## Accounting` → `### Steering` in the issue's receipt (`receipts/issue-<N>.md`), and that ledger is well-formed. Steering rows are v2, 9 columns (`steer-key | session | issue | type | tier | user-reason | commit | ordinal | timestamp`). `ordinal` and `timestamp` are the event's **absolute transcript coordinates**: `ordinal` is its 1-based position in the session's deterministic event stream, and dedup is identity-based — a `(session, ordinal)` pair is appended once, ever. `type` is one of `interrupt`/`correction`, `tier` is one of `structural`/`classifier`/`lexical`, `issue` is `#N` and matches the receipt that homes the row (every accounted event resolves to an issue — issue #201, decision 6: the hook refuses to write an event it cannot attribute), and `steer-key` is globally unique across `receipts/*.md`. Within a receipt, row order is monotonically non-decreasing in the embedded epoch (append-only) and per-session `ordinal`s are strictly increasing; the same `(session, ordinal)` may not appear in two receipts (a duplicate is a cross-branch re-append, and now detectable).
- **Rationale**: Token-accounting captures *machine* cost; steering-accounting captures *human* steering cost — the moments where the operator interrupted a turn or redirected the agent. These are the highest-signal record of where the agent's instructions are misaligned with intent, and the commit history otherwise shows the result of a redirect, never the redirect itself. A durable per-issue receipt row turns each steering event into a citable record. **Why no commit trailers (issue #293)**: the directive used to stamp an always-on summary triple (`Steer-Count`/`Steer-Types`/`Steer-Tiers`) onto every commit. The triple was a `git log`-skimmable copy of facts already in the receipt rows, and its only enforced contract was "the stamped count equals the rows this commit staged" — a self-referential check that becomes vacuous once the stamp is gone. Steering completeness was always best-effort regardless: the pre-commit extractor is non-blocking (a transient classifier failure logs and exits 0 rather than blocking a commit), so the directive never guaranteed "every transcript event is recorded", only that whatever rows exist are valid. Dropping the trailers therefore loses no real guarantee — it removes a denormalised copy and the squash-merge HEAD-fallback that re-validated it — while `validate-dir` retains every substantive invariant: per-row shape, type/tier sets, receipt-homed issue, append-only epoch order, per-session ordinal strict-increase, global steer-key uniqueness, and cross-receipt `(session, ordinal)` identity. Homing rows in `receipts/issue-<N>.md` rather than a central `STEERING.md` (issue #201) makes the write target conflict-free and bounded. **Event-sourcing the dedup (issue #229)**: the old positional dedup ("skip the first N transcript events") re-appended and misattributed events across branches; recording each event's `(session, ordinal)` makes dedup an identity test and a cross-branch duplicate detectable post-merge. Two-tier detection: tier 1 (interrupts) reads runtime sentinels with near-zero false positives; tier 2 (corrections) shells out to the runtime's headless CLI for semantic classification, falling back to a regex pre-filter only when the CLI is unreachable. **Tool denials are excluded by design** — a "deny" click is usually "I'll do it myself", not an intent redirect. Privacy is the directive's single load-bearing tradeoff: `user-reason` is committed verbatim in the receipt row (and now nowhere else — it is no longer duplicated into a commit trailer). The directive is mandatory (`always_install: true`) — in this kit's model every commit is agent-authored, so steering-accounting is part of the audit chain.
- **Enforced by**: `.governance/packs/governance-kit/audit/directives/agent-steering-accounting/check.sh` runs the repo-wide ledger-shape check (`lib/ledger.py validate-dir`) in both modes — the only contract the directive enforces now that the summary trailers are retired. The sibling `hooks/pre-commit.sh` extracts events from the active session JSONL (via `runtimes/<runtime>.sh`) and appends rows as a side effect; the bootstrap hook generator wires it into `.githooks/pre-commit` and `check.sh` into `.githooks/commit-msg`. `lib/extract.py` houses the two-tier detection, `lib/ledger.py` the row I/O, and `lib/conf.py` reads the per-repo configuration. Two knobs are tunable per repo via the overlay `.governance/conf/governance-kit/audit/agent-steering-accounting.conf` layered over the directive's `defaults.conf`: the lexical-fallback trigger phrases and `CANDIDATE_MAX_LEN` (default 2000; env `GOVERNANCE_CANDIDATE_MAX_LEN` wins). Neither knob affects the `check.sh` contract — they only shape which events the extractor records.
- **Exceptions**: Revert commits are exempt (subject starts with `Revert "`); merge commits never reach the commit-msg hook. Commits authored outside a recognised agent runtime simply record no steering (the pre-commit extractor no-ops); `check.sh` still validates whatever rows already exist. Historical commits pre-dating #66 may carry `Steer-Key:` trailers; they are ignored. Legacy v1 rows (7 columns, no `ordinal`/`timestamp`) keep parsing and are validated to the v1 rules — excluded from the `(session, ordinal)` duplicate and ordinal-monotonicity checks. A `(session, ordinal)` duplicate that is genuinely irreparable (a cross-branch re-append already merged to the trunk) is covered by a `governance: allow-agent-steering-accounting <reason>` waiver token (reason required); the audit trail is `git log --grep='allow-agent-steering-accounting'`. `SKIP_GOVERNANCE=1 git commit ...` and `git commit --no-verify` skip the local hooks; CI re-runs the ledger-shape check.

> **Privacy note.** `user-reason` cells preserve text from interrupt-with-reason events and tier-2 correction messages. Tier-2 (`tier: classifier`) records the LLM-summarised redirect intent; tier-2 (`tier: lexical`) records verbatim user text only when the runtime CLI is unreachable and the regex fallback runs. In all cases the recorded text becomes part of the repo's public history. **Do not install on a public repo without thinking through what those messages could leak.**

> **Installation note.** The directive folder is self-contained — `lib/` (extract, ledger, receipt_io, conf, classifier), `hooks/pre-commit.sh` (the side-effect extractor), and `runtimes/` (per-runtime transcript readers) install as a unit. There is no `prepare-commit-msg` hook (issue #293 retired the summary trailers) and no central ledger asset — receipts are created on demand by the hook. See this directive's `README.md` for runtime wiring and the extractor's two-tier model.
