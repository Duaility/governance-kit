# Security

`governance-kit` is a developer-tooling project. The skills and scripts in
this repository execute locally against a user's checkout — they do not
operate on remote data, open network connections, or hold credentials.

## Reporting a vulnerability

If you believe you've found a security issue in the rules, hooks, or
skills shipped here — for example, a rule check that can be coerced into
executing attacker-controlled input, or a bootstrap path that writes
outside the intended governance surface — please report it privately.

- **Preferred:** open a [GitHub security advisory](https://github.com/Duaility/governance-kit/security/advisories/new)
  on this repository. Advisories are private until we publish a fix.
- **Alternative:** email the maintainer at `srikanth@crowdshakti.com`
  with `[governance-kit security]` in the subject.

Please include a reproduction, the affected commit, and the impact you
observed. We aim to acknowledge reports within five business days.

## Scope

In scope:

- The rule checks under `governance-bootstrap/assets/packs/*/rules/*/check.sh`.
- The hook dispatchers generated by `governance-bootstrap/assets/packs/lib/hooks.sh`.
- The installer helpers under `governance-bootstrap/assets/packs/lib/install.sh`.
- The `governance-reset` skill's uninstall paths.

Out of scope:

- Vulnerabilities in the target repositories that bootstrap these skills.
  Governance-kit inherits the target repo's trust boundary — it does not
  extend it.
- Downstream runtime bugs in Claude Code, Codex CLI, or other agent runtimes.

## Disclosure

Once a fix is ready, we coordinate a release and publish the advisory
with credit. There is no bug bounty.
