# issue-172 — deterministic lifecycle apply: move verb execution off LLM prose

Closes [#172](https://github.com/Duaility/governance-kit/issues/172).

The lifecycle verbs are deterministic primitives glued together by LLM-executed prose. Issue #170 moved the *plan* half of `governance kit update` into `kitverb.py kit-plan` because hand-assembled plans silently went wrong; the *apply* half — per-file `cp` + `stamp_managed_marker`, hook regeneration, `install.yaml` rewrite, smoke test — remained ~250 lines of UPDATE_FLOW.md prose the agent executed step by step, none of it unit-testable. This change completes the terraform-style plan/apply split for the lifecycle verbs: a pure **plan** that resolves everything before any write, and a tested **apply** engine that executes it in one call. The operator (agent or human) keeps what is genuinely theirs — eliciting decisions, showing diffs, the commit — and stops being the executor.

This PR lands the migration in phases on one branch, under this one issue (no multi-PR epic): **Phase 1** — `kit update` (`kit-plan --diff` + `kit-apply`). **Phase 2** — `pack {add,update,remove}` (`pack-plan` + `pack-apply`), plus the shared `applylib.py` apply-helpers and `docsurgery.py` CONSTITUTION.md surgery the later phases reuse. Phases 3–4 (reset/uninstall, init) follow in subsequent commits on this same branch.

## What changed

- kit-plan `--diff` emits per-file unified diffs computed against the stamped source — **`governance/assets/packs/lib/kitverb.py`**: each `files[]` entry carries the unified diff from the current destination to the source template with the new `kit-version=` already applied (`stamped_text()` is the Python mirror of install.sh `stamp_managed_marker`, same contract), so the marker line never shows as spurious noise and the agent no longer hand-stamps temp copies to compute diffs. `cmd_kit_plan` was refactored around a pure `compute_plan(root)` shared with the new subcommand.
- kit-apply executes the update deterministically in one tested call — new **`governance/assets/packs/lib/kitapply.py`**, dispatched as `kitverb.py kit-apply <root> [--decisions <json|file>] [--dry-run] [--force] [--record-pre-tracking] [--owner <o> --repo <r>]` (repo-hygiene's 500-line limit pushed the engine into its own module; it imports `compute_plan`/`stamped_text` from kitverb). It **recomputes the plan at execution time** (never trusts a stale one) and enforces in code every gate that used to be prose: refuse on `downgrade` and `no-recoverable-pin`; refuse on `pre-tracking` without `--record-pre-tracking` (the flag *is* the recorded consent); refuse on a reconstructed pin without `--owner`/`--repo`; refuse on a dirty working tree without `--force`; refuse a decisions object that names destinations with nothing to decide. Then, in order: writes each approved file pre-stamped (mode preserved), honors per-file decisions (backups as `<path>.pre-update.bak`), regenerates hook dispatchers via hooks.sh `generate_hooks_for_strategy` under the manifest's `hook_strategy` (byte-compared to report `regenerated` vs `unchanged`), writes `kit_version` through to `install.yaml` — an in-place line edit that preserves every other field when the manifest exists, a fresh v3 manifest via install.sh `write_installed_manifest` on the reconstructed path — smoke-tests `bash <tests_dir>/run.sh` (failure is surfaced, never aborts), and prints a JSON report (`result` / `updated` / `added` / `skipped` / `kept` / `unmanaged` / `backups` / `hook_dispatcher` / `manifest` / `smoke_test` / `assumptions`; exit 0 applied/up-to-date/dry-run, 2 refused, 1 error). The dirty-tree gate doubles as the rollback story: every path written is tracked, so `git checkout -- .` restores a clean tree if a late step fails — no partial-state bookkeeping.
- per-file decisions cover managed and unmanaged files — `--decisions` accepts `keep` / `apply` / `overwrite-with-backup` per destination; managed files (marker present) default to `apply` because the marker is the regeneration contract, unmanaged ones default to `keep` and are never silently overwritten. A managed hand-edited file can be held back with an explicit `keep`.
- UPDATE_FLOW.md Steps 3–5 collapsed onto the kit-apply contract — **`governance/references/UPDATE_FLOW.md`**: Step 1 plans with `--diff`; Step 2's pre-tracking branch maps consent to `--record-pre-tracking`; Step 3's hand-computed diff-status/diff-text block is deleted (both come from the plan); Step 4 collects the per-file decisions JSON (managed hold-backs included); Step 5 is now a single `kit-apply` invocation plus the report-field contract, replacing the six-step cp/stamp/hook/manifest/smoke prose; Step 7 stages from the report and never stages `*.pre-update.bak`; key principles gain **"Plan and apply are both deterministic"**.
- SKILL.md, VERBS.md, and the kit-update evals synced — **`governance/SKILL.md`** and **`governance/references/VERBS.md`** name the plan/apply pair in the `kit update` invariants (the skill never hand-executes file operations); **`governance/evals/kit-update/evals.json`** rewords evals 1, 5, 6 to the kit-apply mechanism, and eval 1 gains the assertion that the apply ran via `kit-apply` rather than hand-executed shell steps.
- 13 new contract tests in scripts/test-kitverb.py — against throwaway git repos: forward apply (stamping, manifest write-through preserving sibling fields, hook generation, smoke test), up-to-date purity (tree digest unchanged), downgrade / no-recoverable-pin / dirty-tree refusals + `--force`, unmanaged keep/overwrite-with-backup, managed `keep` override, bad-decisions rejection, `--dry-run` purity, pre-tracking consent, reconstructed fresh-manifest path, and `kit-plan --diff` shape. Fixture repos strip inherited `GIT_*` env (same guard as scripts/test.sh).

### Phase 2

- applylib.py holds the shared apply-helpers; kitapply.py refactored onto it — new **`governance/assets/packs/lib/applylib.py`** owns the primitives every apply engine needs (`git_dirty` — the dirty-tree gate that doubles as the `git checkout -- .` rollback story; `bash_lib` to run snippets with install.sh/hooks.sh sourced; `regenerate_hooks` composing `build_hook_spec_from_installed_directives` + `generate_hooks_for_strategy`; `hook_digests` for the regenerated-vs-unchanged report; the non-fatal `smoke_test`; and the JSON `refuse`). kitapply.py drops its private copies and imports them, so kit/pack/reset/uninstall/init never re-implement the same gates.
- docsurgery.py does pure CONSTITUTION.md subsection surgery — new **`governance/assets/packs/lib/docsurgery.py`**: a directive's subsection *is* its `constitution.md` (a `### <id>` block running to the next `### `/`## ` heading), so `strip_directive_subsection`, `upsert_directive_subsection`, and `append_evolution_log` are pure string→string transforms (the engines own file I/O). The heading is exact-matched, so a prefix id (`doc` vs `doc-freshness`) never aliases. This is the surgery `pack remove`, `reset`, and `init` all did by prose `Edit`.
- pack-plan resolves add/update/remove with per-directive diffs — new **`governance/assets/packs/lib/packplan.py`**, dispatched as `packverb.py pack-plan {add|update|remove} <root> [<ref-or-id>] [--diff]`. `add`/`update` fetch into the SHA-addressed cache (never the working tree — the only network, analogous to terraform refresh), validate, capability-check, and classify each directive `add`/`update` with a `diff -ruN`-shaped folder diff; `update` reads the lockfile and marks SHA-unchanged packs `skip` and `local` packs skipped-with-reason; `remove` is fully offline, listing directive folders and flagging which CONSTITUTION subsections are present. It composes packverb's existing `fetch_ref`/`capability_violations`/`load_lockfile` and packctl's `validate_pack_dir`.
- pack-apply executes pack add/update/remove deterministically in one tested call — new **`governance/assets/packs/lib/packapply.py`**, dispatched as `packverb.py pack-apply {add|update|remove} <root> [<ref-or-id>] [--decisions <json>] [--dry-run] [--force]`. It recomputes the plan, enforces in code every gate that was prose — refuse on pack validation or capability violations, on a dirty tree without `--force`, on removing `governance-kit/core` wholesale, on a pack absent from the lockfile — then for add/update installs each approved directive folder via `install_directive_folder` + `install_directive_assets`, records newly-seeded files in `install.yaml`'s `install_assets_seeded` (in-place, idempotent), regenerates hooks, and upserts the lockfile pin **last**; for remove it deletes folders, strips each CONSTITUTION subsection via docsurgery, drops the empty pack root, regenerates hooks, and prunes the lock **first**. `--decisions {"<id>": "skip"}` holds individual directives back. JSON report; exit 0 applied/up-to-date/dry-run, 2 refused, 1 error.
- PACK_VERBS.md add/update/remove prose collapsed onto the pack-apply contract — **`governance/references/PACK_VERBS.md`** gains a "Deterministic plan/apply" section and rewrites the `pack add` (9 steps → plan/diff/apply/report), `pack update` (4 steps → plan/diff/apply), and `pack remove` (7 steps → plan/apply) flows onto the two commands; the hand-executed `install_directive_folder` loops, `generate_hooks_for_strategy` calls, `lock-add`/`lock-remove` invocations, `rm -rf`, and CONSTITUTION edits are gone. **`governance/references/VERBS.md`** names the plan/apply pair in the `pack *` summary.
- 13 new contract tests in scripts/test-packverb-apply.py wired into test.sh — six pure docsurgery transforms (strip/upsert/append, prefix-no-alias, absent no-op); four `add` cases run in-process with `packplan.fetch_ref` stubbed to a local pack (no network) — install + lockfile + hooks + seeded-asset ledger, `--dry-run` purity, capability-violation refusal, per-directive `skip`; three `remove` cases via the real CLI (offline) — folder delete + subsection strip + lock prune, the `governance-kit/core` guard, and the absent-pack refusal. Wired as a new `test.sh` layer.

### Phase 3

- reset-plan/reset-apply restore directives to the pinned lockfile SHA — new **`governance/assets/packs/lib/resetplan.py`** + **`resetapply.py`**, dispatched as `packverb.py reset-{plan,apply} {directive|pack|all} <root> [<target>] [--drop-handauthored] …`. The plan resolves the in-scope directive set, builds a SHA-pinned ref (`gh:owner/repo[/subpath]@<sha>`) and fetches the pinned source into the cache (re-fetch if missing, abort on failure — never a partial reset), classifies each `restore`/`skip` (byte-identical)/`drop`, and emits the `installed → pristine` folder diff under `--diff`. The apply restores folders via `copy_tree_without_evals`, replaces/inserts CONSTITUTION subsections via docsurgery from the pinned `constitution.md`, drops hand-authored dirs + strips their subsections under `--drop-handauthored`, regenerates the hook dispatcher, appends one Evolution Log entry per pack (`--date`/`--author` operator-supplied), and smoke-tests. Refuses on missing lockfile (reset is lockfile-driven), empty scope, and a dirty tree without `--force`; leaves `.governance/freshness.conf` untouched.
- uninstall-plan/uninstall-apply reverse every init side-effect, soft/hard/dry-run — new **`governance/assets/packs/lib/uninstallplan.py`** + **`uninstallapply.py`**, dispatched as `packverb.py uninstall-{plan,apply} <root> [--mode soft|hard|dry-run] [--allow-heuristic]`. The plan surveys the repo against the UNINSTALL_MATRIX (manifest → marker → heuristic), classifies it (`fully-installed`/`partial`/`unmarked-collision`/`none-detected`), and inventories marked hooks, `.userhook` restores, collisions, the AGENTS.md marker state, tree deletes, Path-B entries, seeded docs, and `.pre-governance.bak` backups. The apply executes the reversal in the fixed Step-5 order (hooks → `core.hooksPath` unset → AGENTS.md block strip → CONSTITUTION/CI/enable-script → Path-B → seeded docs (hard) → backups (hard) → `.governance/` last). It is idempotent (`none-detected` → no-op), refuses an `unmarked-collision` (never deletes an unmarked hook), and refuses a destructive mode under heuristic source-of-truth without `--allow-heuristic`. No git-destructive ops, no commit.
- docsurgery gains marker-block strip for the AGENTS.md directive block — **`governance/assets/packs/lib/docsurgery.py`** adds `strip_marker_block(text, open, close)`: paired markers → delete the inclusive span + trailing blank line (`stripped`); opening-marker-only → strip to the next `## ` heading (`unbounded-stripped`, recorded as an assumption); neither → `absent`. Span removal is byte-safe by construction, so the prose's byte-diff guard can never trip.
- lifecycle_cli.py keeps packverb.py under the 500-line limit — the six lifecycle subparser registrations (pack/reset/uninstall plan+apply) moved out of `packverb.py main()` into new **`governance/assets/packs/lib/lifecycle_cli.py`** `register_lifecycle(sub)` (lazy engine imports, same cycle-avoidance as before), bringing packverb.py from 502 back to 446 lines — repo-hygiene's 500-line ceiling holds.
- RESET_FLOW.md and UNINSTALL_FLOW.md execution prose collapsed onto the engines — **`governance/references/RESET_FLOW.md`** gains a "Deterministic plan/apply" section and rewrites Steps 3–6 (locate-source / confirm / execute-restore / stage) onto `reset-plan`/`reset-apply`, deleting the hand-executed folder-replace, subsection-restore, freshness-clear, hook-regen, and Evolution-Log prose; **`governance/references/UNINSTALL_FLOW.md`** gains the same section and collapses Step 5's eight-step ordered-delete prose onto `uninstall-apply`. **`governance/references/VERBS.md`** names the plan/apply pair in the `reset` and `uninstall` entries.
- 12 new contract tests in scripts/test-reset-uninstall.py wired into test.sh — six `reset` cases run in-process with `resetplan.fetch_ref` stubbed to a local pinned source (no network): drifted-directory restore + subsection restore + Evolution Log append, pristine `skip`, missing-lockfile refusal, unknown-directive refusal, dirty-tree refusal + `--force`, `--dry-run` purity; six `uninstall` cases via the real CLI (offline): soft (managed removed, seeded + backup preserved, AGENTS block stripped, `core.hooksPath` unset), hard (seeded + backups deleted), `--dry-run` purity, `none-detected` no-op, `unmarked-collision` refusal, heuristic refuse-without-opt-in + dry-run-allowed + `--allow-heuristic` proceeds. Wired as a new `test.sh` layer.

## Out of scope

- **The commit.** `kit-apply` writes and reports; staging and the atomic commit stay with the operator. The accounting populators (`agent-token-accounting`, `agent-steering-accounting`) read the live agent transcript at commit time — a Python-driven commit would sever that, and the issue anchor (`AGENT_ISSUE`) is operator knowledge.
- **Interactive elicitation.** The per-file questions and the explicit `yes` remain the skill's job; `kit-apply` consumes their serialized result (`--decisions`). Decisions serialize; conversations don't.
- **`--allow-downgrade`.** The deterministic apply makes a safe downgrade implementable (it only trusts the recomputed plan), but it stays refused until a real use case lands.
- **Seeded-asset deletion on `pack remove`.** Apply prunes nothing from the repo root and leaves the `install_assets_seeded` ledger as-is on remove: the installed directive folder excludes `install-assets/`, so there is no reliable source-of-truth mapping a seeded file back to the removing pack, and the seeded docs (`QUALITY.md`, `COSTS.md`) are usually hand-edited. Deleting them belongs to `uninstall --hard`, which has the manifest ledger and the explicit mode.
- **Pack seeded-asset *recording* across re-adds.** `install_assets_seeded` is append-and-dedupe; a file already present is not re-seeded and not re-ledgered. Garbage-collecting stale ledger entries is left to uninstall.

## Decisions

- **Forced change: priced `claude-fable-5` in the token-accounting rate table.** The `agent-token-accounting` pre-commit populator refuses any commit whose session model is unpriced, and this session runs on `claude-fable-5` — so no commit (including this one) could land without the row. Added a `claude-fable` family fallback + `claude-fable-5` version row (10.00 / 12.50 / 1.00 / 50.00 per MTok — $10 in, $50 out from the current Anthropic rate card, with the standard 1.25× 5-minute cache-write and 0.1× cache-read multipliers) to both copies per the pack/dogfood dual-edit convention: `packs/core/directives/agent-token-accounting/lib/rates.py` and `.governance/packs/governance-kit/core/directives/agent-token-accounting/lib/rates.py`. Verified via the `cost` CLI (`claude-fable-5` and a date-suffixed variant both resolve). Folded in rather than split out because the repo's one-issue-one-PR discipline leaves no way to land a prerequisite PR mid-stream, and the change is two rows.
- **This deliberately reverses the #170 "monolithic apply driver — out of scope" decision.** That receipt argued a single driver "contradicts the kit's architecture (granular pure helpers + prose orchestration)" and "would re-implement a large interactive surface". The architecture direction was re-decided in this issue: prose orchestration of mechanical steps is the drift surface, not a feature, and the interactive-surface objection dissolves once decisions are serialized as data (`--decisions`) instead of conversation. The granular helpers survive — `kit-apply` composes `generate_hooks_for_strategy` and `write_installed_manifest` rather than re-implementing them.
- **Manifest write-through is an in-place line edit, not a `write_installed_manifest` re-emit.** Re-emitting needs every init-time flag (collisions, seeded assets, path_b) round-tripped through the apply; a line edit can't lose what it never touches. `generated_at` is left alone — it records the init, and rewriting it would make the apply wall-clock dependent. The fresh-manifest path (reconstructed pin) still uses `write_installed_manifest`, because there is nothing to preserve.
- **Managed files default to `apply`, unmanaged to `keep`.** The line-2 marker is the regeneration contract (same rule the hook generator enforces), so kit-owned files update by default; an unmarked file is somebody else's and is never silently overwritten. The interaction-policy row for hand-edited managed files is preserved as an explicit per-file `keep` / `overwrite-with-backup` override rather than a byte-diff prompt — across versions every managed file byte-differs, so "hand-edited" is not mechanically distinguishable from "template evolved".
- **One issue, one PR, one growing receipt — phases land as commits, not separate issues.** The user asked for the remaining lifecycle work in this same PR. That matches the repo's no-multi-PR-epics discipline: each phase is a commit on this branch under #172, and this receipt grows with it rather than spawning `issue-173`/`issue-174`. Because the receipt is not yet on `main`, doc-integrity's frozen-files rule does not bite the in-branch edits (the frozen baseline is `origin/main`).
- **`docsurgery` is a separate module from `applylib`.** Apply-execution helpers (gates, hooks, smoke) and CONSTITUTION text surgery are different concerns with different reuse sets — surgery is also wanted by `directive *` flows that are not apply engines — so they are split. Both are pure/near-pure and independently testable.
- **`pack-plan add/update` fetches inside the "pure" plan.** Fetch writes only to the SHA-addressed immutable cache, never the working tree, so the plan stays side-effect-free *with respect to the repo* — the property the apply gate and rollback story depend on. This mirrors a terraform refresh and is what lets the plan show the exact `check.sh` a pack would run before approval.
- **`reset` leaves `.governance/freshness.conf` alone.** RESET_FLOW.md's prose said reset "clears freshness.conf thresholds for in-scope directives", but the file's actual format is a list of opt-in **doc paths**, not per-directive thresholds — so the prose describes a feature the file never had. Deleting lines that merely mention a directive id risks dropping a user's doc opt-in. The safe, correct reading: reset restores directive folders + subsections + hooks and leaves freshness.conf untouched. Recorded here as the deliberate divergence from the prose.
- **The Evolution Log date/author are operator-supplied (`--date`/`--author`), not read from wall-clock.** Apply engines avoid `date`/`git config` reads so they stay reproducible and testable; the operator (who already owns the commit) passes today's date and their git user. With no `--date`, reset skips the log append rather than inventing a date.
- **uninstall's heuristic mode needs `--allow-heuristic`, mirroring the prose's "force dry-run when the manifest is missing".** Rather than silently degrade to dry-run (which could read as "nothing to do"), the engine refuses a destructive mode and names the flag — explicit opt-in, with `--mode dry-run` always available for a preview. "Silence is not consent" becomes a code gate, not a prose hope.
- **An `unmarked-collision` refuses rather than prompting per-hook.** The three-way wrap/skip/overwrite choice the prose offers is interactive elicitation; the deterministic apply surfaces the colliding hooks and stops, leaving the resolution (restore the `.userhook`, or move the hook aside) to the operator before a re-run — the same "decisions serialize, conversations don't" split as `kit-apply`.
