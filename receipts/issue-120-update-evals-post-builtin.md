## What changed

- `governance/evals/init/evals.json` updated so the post-init lockfile assertion expects `governance-kit/core` with `source: gh` (ref + 40-char SHA + subpath `packs/core`) instead of the retired `source: builtin`. The assertion now reads `source: gh, ref gh:duaility/governance-kit/packs/core@<v>, real 40-char SHA pin, subpath packs/core` — matching what `init` produces post-#117 when it does `pack add gh:duaility/governance-kit/packs/core@<rev>` instead of the old bundled-tree copy.
- `governance/evals/directive/evals.json` case 6 rewritten: amending an upstream-pinned directive routes through fork-not-patch (`replaces: governance-kit/core/secrets-hygiene` on a forked copy in a `source: local` pack), not in-place editing of the read-only fetched tree. The previous expected behavior was a refusal ("kit-managed and can only be removed via directive remove, never added or modified locally"), which made sense when `governance-kit/core` was bundled and conceptually frozen. Post-#118 the upstream tree is reconstructable (the reconciler clobbers any in-place edit on the next rebuild), so the only durable amendment path is to fork into a local pack with the new `replaces:` field from #119. Assertion list rewritten to check that the upstream pack's tree is byte-identical to the fixture (the fork landed elsewhere, in a `source: local` pack), and that any forked copy carries the `replaces:` declaration.
- `governance/evals/reset/evals.json` case 1 rewritten: pristine source resolves from the pack cache, not from a kit-bundled tree, since core is now a `gh`-fetched pack like any other. The expected_output now references `${GOVERNANCE_KIT_HOME:-~/.governance/cache}/packs/governance-kit__core@<sha>/packs/core/directives/secrets-hygiene/` as the pristine source, with `packverb fetch` re-populating the cache when missing — the same flow `reset` runs against `acme/widgets`, no special-case branch for the kit's pack. The "(source: builtin)" parenthetical in the first assertion is corrected to "(source: gh)".
- `governance/evals/pack/evals.json` cases 4, 5, 6, 7 updated: `pack update` runs the same flow against `governance-kit/core` as against community packs (no special-case skip); `pack remove governance-kit/core` is identity-guarded rather than source-discriminator-guarded; `pack list` shows core with `source: gh` + sha + ref columns populated. Case 4: removed the "silently skipped governance-kit/core" assertion; the new assertion is "processed governance-kit/core through the same pack update flow." Case 5: rewrote the "is NOT source: builtin (refuses on governance-kit/core)" guard to "is NOT governance-kit/core (the kit's own pack is refused on identity, not on a source: discriminator — both are source: gh post-#117)." Case 6 (`pack list`): assertion that core appears with empty sha column flipped to expect a populated 40-char sha + a `gh:duaility/governance-kit/packs/core@<v>` ref. Case 7: dropped the "(not builtin)" qualifier from the local-pack confirmation; the source-discriminator-symmetry assertion now reads "the kit's own pack is identity-guarded, regardless of source."
- Fixture lockfiles in `governance/evals/{directive,pack,reset}/files/*/.governance/packs.lock` rewritten: `governance-kit/core` entry switched from `source: builtin` to `source: gh` + fixture ref + fixture sha + subpath. Each of the four affected fixtures (`directive/files/seeded-repo`, `pack/files/repo-with-installed-pack`, `pack/files/seeded-repo`, `reset/files/drifted-repo`) now records `governance-kit/core` with `source: gh`, `ref: gh:duaility/governance-kit/packs/core@v0.2`, `sha: b33ec7a05be6c157a63b5f1a22d0102a1bf5a50c` (the phase 1 commit's sha; deliberately consistent across fixtures), `subpath: packs/core`, `min_governance_kit: ""`, and `installed_at: 2026-05-08T13:00:00Z`. The local-pack entries (`acme/seeded-repo`, etc.) are unchanged — they were already `source: local`.
- Fixture `pack.yaml` files: artifactual `source: builtin` line deleted (real `packs/core/pack.yaml` carries no `source:` field, so the fixtures now match). The four `governance/evals/*/files/*/.governance/packs/governance-kit/core/pack.yaml` files all carried a `source: builtin` line that didn't match the real pack manifest format. The line is removed; the remaining fields (`id`, `name`, `version`, `min_governance_kit`, `description`, `author`) match the real `packs/core/pack.yaml` shape.
- Fixture README files (`governance/evals/{directive,pack,reset}/files/**/README.md`): narrative mentions of `source: builtin` replaced with the gh-only phrasing. The directive/files/README.md case 6 reference also gets a wording update — the old text said "refuse to modify a builtin-owned directive"; the new text says "route a modify of an upstream-pinned directive through fork-not-patch (`replaces:`) instead of editing the read-only fetched tree" so the fixture description matches the new eval expected behavior.

## Out of scope

- Adding new eval cases for the `replaces:` field, `directive disable`/`sync` verbs, or the reconcile flow. Those need new fixture repos AND new SKILL.md content to drive the agent through the new paths; landing them belongs with the runtime suppression follow-up to #119 and the verbs being implemented in subsequent issues, not in a fixture-cleanup pass.
- Updating the `init/evals.json` assertion that the workflow file pins third-party actions by SHA. Unrelated to the gh-only model migration; tracked separately.
- Cleaning up `governance/evals/uninstall/` — those fixtures don't reference `source: builtin` (uninstall doesn't branch on source) and don't need updating.
