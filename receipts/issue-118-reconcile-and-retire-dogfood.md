## What changed

- New helper `governance/assets/packs/lib/reconcile.sh` — walks `.governance/packs.lock`, fetches every `gh` pack via `packverb fetch`, and rebuilds `.governance/packs/<id>/` from the cache (or working tree, via the resolver from #115). Prunes directives not listed in the lockfile so a pack can ship more than the consumer installs. Implementation snapshots the lockfile JSON to a tempfile (older bash + heredoc-inside-process-substitution emitted an empty stream during testing), reads the gh-source rows as `<id>\t<ref>\t<sha>\t<subpath>\t<dir1,dir2,...>`, and for each row: calls `pv fetch "${ref}@${sha}"` to populate (or hit) the cache, parses the `pack_dir` from the JSON response, removes the existing `.governance/packs/<id>/` and recreates it via `cp -R <pack_dir>/. <target>/`, then walks `directives/*/` and `rm -rf`s any subdirectory whose id isn't in the lockfile's directives list. Marks check.sh and hooks/* / runtimes/* executable. Local-source packs are counted-but-skipped — they are first-party committed source.
- `packverb lock-read` serializes `datetime` values to ISO strings via `default=str` — required so `reconcile.sh`'s python pipeline can parse the lockfile's `installed_at` timestamps. The change is one argument to `json.dumps(...)` in `cmd_lock_read`; YAML's autoload of RFC 3339 strings to native `datetime` objects (a feature that's useful for CLI consumers expecting structured time) was previously opaque to the JSON pretty-print path. With `default=str`, datetimes round-trip as ISO 8601 strings without forcing the loader to use `yaml.BaseLoader` (which would lose the typed-list semantics for `directives` lists).
- `.gitignore` excludes `.governance/packs/governance-kit/` so the rebuilt expanded tree of the kit's own core pack is no longer tracked. Hand-authored repo-local packs (lockfile `source: local`) stay committed. The new gitignore block carries a comment block explaining the model — fetched packs are reconstructable artifacts, hand-authored packs are source. The kit's own `governance-kit/core` is `source: gh` post-#117 and falls in the rebuild bucket.
- `git rm -r --cached .governance/packs/governance-kit/` retires the dogfood mirror from tracking. The expanded copy now exists only as a reconcile-rebuilt artifact, eliminating the dual-edit footgun. Until this commit, every directive change had to land twice — in `packs/core/directives/<id>/` (the source) AND in `.governance/packs/governance-kit/core/directives/<id>/` (the dogfood mirror) — to keep this repo's runtime in sync with its own source-of-truth. The memory note "Pack + dogfood dual edit" exists precisely because of this footgun. With the mirror untracked + reconciler available + `.gitignore` covering the path, the dual edit is no longer required: edit `packs/core/directives/<id>/check.sh` once, run `reconcile`, and the mirror at `.governance/packs/governance-kit/core/directives/<id>/check.sh` is rebuilt.
- `bash scripts/test.sh` and `bash .governance/run.sh` both pass with the new model — full kit suite green and all 14 directives green against the rebuilt mirror. The pre-commit hook gate runs `scripts/test.sh` (every layer including pack evals) and `.governance/run.sh` (every installed directive); both completing successfully is the fix-point that the new model preserves contract-equivalence with the old one. The reconcile-then-run flow works because the dogfood lockfile pins `governance-kit/core` to `gh:duaility/governance-kit/packs/core@v0.2`, and the working-tree resolver short-circuits `pv fetch` to read from the live `packs/core/` tree at HEAD.

## Out of scope

- Auto-invoking `reconcile.sh` from `run.sh`. Consumers that have already run `governance init` get a populated `.governance/packs/<id>/` tree — the reconcile is needed only on fresh clones (where the gitignored tree is absent) or after `pack update` bumps a sha. Wiring it into run.sh would also require `packverb.py` to be reachable at runtime in consumer repos, which it isn't (the kit ships as a skill bundle, not vendored into each consumer). The agent-driven `governance` skill calls reconcile explicitly during the relevant flows; that's the supported integration point for now. A future PR may explore shipping a consumer-side `bin/reconcile` shim if the rebuild step turns out to need automatic triggering.
- Fork-not-patch amendments. Phase 5 of #114 — separate issue.
- Cleaning up tutorial / blog markdown that still mentions the legacy bundled-mirror model. Those don't drive runtime; updating them is a follow-up doc-pass once the model fully settles.

- `bash .governance/run.sh` exits 0 with all 14 directives green — proves the reconciled `.governance/packs/governance-kit/core/` matches what the dogfood mirror used to ship, with the pruning correctly excluding `no-orphan-todos` (which the source pack ships but this repo's lockfile does not install).
- `bash scripts/test.sh` exits 0 — every layer (`packctl`, `packverb`, `working-tree resolver`, `install.sh`, `hooks.sh`, runtime, schema-split, packs) passes. The packverb tests confirm the `default=str` JSON change doesn't regress any lock-read consumer.
- `git ls-files .governance/packs/governance-kit/` returns empty — the mirror is no longer tracked.
- `git status` shows `.governance/packs/governance-kit/core/...` as ignored (untracked + gitignore-matched), not as untracked-but-pendable. Reviewer can confirm by running `git check-ignore -v .governance/packs/governance-kit/core/pack.yaml`.
- Reviewer can verify the model end-to-end by `rm -rf .governance/packs/governance-kit/ && bash governance/assets/packs/lib/reconcile.sh "$(pwd)" && bash .governance/run.sh` — full circle from absent → rebuilt → green.
