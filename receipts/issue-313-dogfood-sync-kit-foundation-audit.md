# issue-313: sync dogfood to kit 0.10.2, foundation 0.5.0, audit 0.6.1; remove docs pack

Post-release dogfood sync. Moves this repo's own `.governance/` consumer tree
from the previous release (kit 0.10.1 / foundation 0.4.2 / audit 0.6.0, docs
0.2.1) to the freshly cut `kit/v0.10.2`, `foundation/v0.5.0`, and `audit/v0.6.1`
tags, and retires the `governance-kit/docs` pack — entirely through the
released/pinned kit's verbs (`kitverb.py` / `packverb.py`), no hand-edits to the
lockfile, the manifest, or the consumed directive bodies. The one hand action is
trimming three stale `CONSTITUTION.md` assembly sections the re-pin/remove
engines do not own (see `## Decisions`).

## Decisions

- Landed the kit re-sync, the two pack re-pins, and the docs removal in a single
  commit — the same shape as prior dogfood-sync commits (#287, #297). The change is
  a coherent "catch up to the last release" unit and reviewing it as one diff is the
  intended consumer experience.
- Re-pinned foundation and audit with `pack-apply add ...@<tag> --force` rather than
  `pack update`: each pack is pinned at an immutable tag, so `pack update`
  re-resolves the *same* tag (no move). The `--force` is over the `kit-apply` changes
  already staged for this same commit, which are intentional — not unrelated drift.
- **Hand-trimmed three stale `CONSTITUTION.md` sections** the verbs do not own:
  the orphan `### kit-version-sync` subsection (the directive was absorbed into
  `managed-tree-integrity`; no `kit-version-sync` directive is installed), the empty
  `## governance-kit/security` section (the security pack was unshipped in #287), and
  the dead `## governance-kit/docs` section header plus its `### no-broken-internal-doc-links`
  orphan (the docs pack is removed here; `internal-doc-links` is re-homed under
  foundation with its current heading). These are CONSTITUTION-assembly drift left by
  past renames/removals that the docsurgery in `pack remove`/`pack add` cannot match
  (it strips a subsection only when the heading exactly matches the pinned directive
  id). Trimming them makes the assembled constitution honestly reflect the installed
  directive set — which is the document's whole job. No directive content changed.
- In-body `governance: allow-toolchain-config` waiver: the kit update regenerated the
  managed `.githooks/*` dispatchers and `.github/workflows/governance.yml` with the new
  `kit-version=0.10.2` marker — the same legitimate toolchain churn the prior
  dogfood-syncs (#287, #297) waived.
- In-body `governance: allow-doc-integrity CONSTITUTION.md` waiver: this commit
  legitimately rewrites CONSTITUTION subsections (the engine-driven upserts plus the
  stale-section trim above), and on macOS the frozen-section grep OOMs on the Evolution
  Log's huge single-line entries — the same waiver the prior dogfood-syncs carried.
