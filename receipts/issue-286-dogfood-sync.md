# issue-286: sync dogfood to kit 0.10.0, foundation 0.4.2, audit 0.5.0; drop security

Post-release dogfood sync, tracked under the release umbrella #283. Moves this
repo's own `.governance/` consumer tree from the previous release to the freshly
cut tags, entirely through the released/pinned kit's verbs — no hand-edits to the
lockfile, the consumed tree, or the manifest.

## Checklist

- [x] kit re-pinned to 0.10.0 and managed runtime files re-synced
- [x] foundation re-pinned to 0.4.2
- [x] audit re-pinned to 0.5.0
- [x] security pack removed
- [x] suite green after the sync

## What changed

Driven by the released `governance` skill delegating to the repo-pinned kit
engines (`kitverb.py` / `packverb.py`); every file below was written by those
engines, not by hand.

- **kit re-pinned to 0.10.0 and managed runtime files re-synced** — `kit-resolve`
  → delegated `kit-apply` (0.10.0's own engine) → `kit-pin` rewrote the pin in
  `.governance/install.yaml` (`kit_version`/`kit_ref`/`kit_sha`) and re-synced the
  three managed runtime files `.governance/run.sh`, `.governance/lib.sh`, and
  `.github/workflows/governance.yml` (the new `lib.sh` carries the shared
  sub-agent-attestation helpers). The hook dispatchers `.githooks/pre-commit`,
  `.githooks/commit-msg`, `.githooks/prepare-commit-msg`, `.githooks/post-commit`,
  and `.githooks/pre-push` were regenerated by the new generator. `enable-governance.sh`
  is no longer managed (de-vendored upstream in #268), so it is not re-synced.
- **foundation re-pinned to 0.4.2** — `packverb pack-apply add ...@foundation/v0.4.2`
  updated `.governance/packs.lock` and rewrote the consumed directive folders
  `.governance/packs/governance-kit/foundation/directives/managed-tree-integrity/constitution.md`
  and `.governance/packs/governance-kit/foundation/directives/managed-tree-integrity/lib/integrity.py`
  (the change that stops digesting local-only hook plumbing).
- **audit re-pinned to 0.5.0** — `packverb pack-apply add ...@audit/v0.5.0` updated
  `.governance/packs.lock` and rewrote the consumed receipt-per-issue directive
  folder: `.governance/packs/governance-kit/audit/directives/receipt-per-issue/check.sh`,
  `.governance/packs/governance-kit/audit/directives/receipt-per-issue/constitution.md`,
  and `.governance/packs/governance-kit/audit/directives/receipt-per-issue/directive.yaml`
  (adds the `## Audit` sub-agent attestation and the file-coverage scope-creep guard).
- **security pack removed** — `packverb pack-apply remove governance-kit/security`
  dropped the three security directives from `.governance/packs.lock`, deleted their
  consumed folders under `.governance/packs/governance-kit/security/`, and stripped
  their three subsections from `CONSTITUTION.md` (unshipped from v0, #278).

## Decisions

- Landed the kit re-sync, both pack re-pins, and the security removal in a single
  commit — the same shape as prior dogfood-sync commits (#258, #266). The change is
  a coherent "catch up to the last release" unit and reviewing it as one diff is
  the intended consumer experience.
- Re-pinned the two changed packs with `pack-apply add <new-tag> --force` rather
  than `pack update`: the packs are pinned at immutable tags, so `pack update`
  re-resolves the *same* tag (no move). The `--force` is over the kit-apply changes
  already staged for this same commit, which are intentional — not unrelated drift.
