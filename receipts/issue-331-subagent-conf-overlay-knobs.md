# issue-331: expose subagent tiers/isolation via the conf overlay

Closes [#331](https://github.com/Duaility/governance-kit/issues/331).

Splits the `subagent:` block's five fields into the *semantic* half that must
stay author-fixed in `directive.yaml` (`inputs`, `checks`, `section`) and the
*operational* half a consumer may tune per-repo (`isolation`, `tiers`). The
operational half is surfaced through the existing pack-owned `defaults.conf` +
`.governance/conf/<owner>/<pack>/<id>.conf` overlay mechanism, resolved with the
same precedence ladder every other knob uses, so behavior is unchanged until a
consumer writes an overlay row.

## What changed

- **subagent defaults.conf rows for isolation and both tiers.** Each sub-agent
  directive now ships a `defaults.conf` carrying `SUBAGENT_ISOLATION=shared`,
  `SUBAGENT_TIERS_ATTEST=low`, and `SUBAGENT_TIERS_SWEEP=high` (with docs that
  spell out the author-vs-operator split and the resolution precedence):
  `packs/audit/directives/receipt-per-issue/defaults.conf` and
  `packs/audit/directives/agent-steering-accounting/defaults.conf`. The rows
  mirror each directive's `directive.yaml` values, so they are the documented
  defaults, not a behavior change.

- **subagent_attest resolves isolation via the conf overlay.** In
  `kit/assets/dot-governance/lib.sh`, `subagent_attest` now resolves
  `isolation` with `conf_get <id> SUBAGENT_ISOLATION "$defaults"`, falling back
  to the `directive.yaml` value (then `shared`) so today's behavior is preserved
  when no overlay row exists. The semantic fields (`inputs`, `checks`, `section`)
  are still read straight from `directive.yaml` — they must not be tweakable
  without a fork.

- **attest path reads SUBAGENT_TIERS_ATTEST and sweep engine reads
  SUBAGENT_TIERS_SWEEP.** New `lib.sh` helpers `_subagent_tier` (reads the
  `tiers: { attest, sweep }` flow map) and `_subagent_tier_resolve` (the conf
  ladder, falling back to the `directive.yaml` value) feed the conf-resolved
  attest tier into the registered ledger row (now a 6-column TSV with a `tier`
  column; `_subagent_register` and `attestation_remediation` updated, with a
  5-column-row back-compat path). A new `_tier_phrase` helper renders the
  requested tier into the grouped/`require_attestation` instruction — the
  low-cost-model request added in #321 — and the orchestrator runs a batched
  shared group at the most capable tier requested. In
  `kit/assets/dot-governance/sweep.py`, a new `resolve_model_tier` resolves
  `SUBAGENT_TIERS_SWEEP` the same way (env > overlay > defaults.conf >
  `directive.yaml`) for any directive carrying a `subagent:` block, while a
  legacy `surface: sweep` directive keeps its top-level `model_tier`; the three
  tier call sites (eval, run, adjudicate) now route through it.

- **author-vs-operator split documented.** `kit/references/SUBAGENT_ATTESTATION.md`
  gains an *Author-owned vs operator-owned* subsection (the knob table + the
  precedence ladder) and a note in *Model tier* that the tier is a tunable
  default; `kit/references/PACK_AUTHORING.md`'s `subagent` schema row makes the
  split explicit. The generated `docs/reference/authoring-packs.mdx` was
  regenerated by `npm run docs:gen`.

- **evals cover overlay-wins and default-fallback for both knobs.**
  `scripts/test-runtime.sh` adds a `#331` section: `_subagent_tier` /
  `_subagent_tier_resolve` (directive.yaml fallback, defaults.conf row, env
  override) and an end-to-end installed-layout test where the user overlay flips
  `isolation`→`isolated` and the attest tier→`high`, asserting the ledger
  columns and the rendered remediation tier phrase. `scripts/test-sweep.py`
  imports the engine and covers `resolve_model_tier` (defaults.conf, overlay
  wins, env wins, directive.yaml fallback, legacy `model_tier`).

## Out of scope

- The semantic fields (`inputs`, `checks`, `section`) stay author-fixed in
  `directive.yaml` — by design (issue #331's own out-of-scope note).
- Wiring the sweep engine to *re-derive* `subagent:` attestation verdicts (the
  immediate #325 follow-up) — this PR only makes the sweep tier conf-tunable for
  a directive that carries a `subagent:` block; it does not make the attest
  directives sweep-surface.
- A `medium` tier in `TIER_MODELS` — the kit maps only `low`/`high` today; the
  helpers degrade an unmapped tier gracefully (`_tier_phrase`/`TIER_MODELS.get`).
- No version-line or `kit-version=` marker changes — those are release-only.

## Decisions

- **`defaults.conf` mirrors the `directive.yaml` value rather than replacing it.**
  The `directive.yaml` keeps declaring `isolation`/`tiers` so an author reads one
  self-contained block, and it is also the ultimate fallback: when no
  `defaults.conf` ships (a directive folder vendored from a pre-#331 release) or
  the conf carries no row, resolution falls back to the `directive.yaml` value.
  `defaults.conf` is the operator-facing default + docs and the conf-mechanism's
  fail-loud anchor. For the two shipped directives both say the same thing, so
  there is no behavior change.
- **Shared-group tier = the most capable tier requested.** The orchestrator
  batches `isolation: shared` sections into one sub-agent; when batched
  directives disagree on attest tier it runs the group at the highest requested
  tier so no directive is under-resourced (raising a tier is the consumer asking
  for *more*).
- **Sweep-side conf resolution reimplemented in Python.** `lib.sh`'s `conf_get`
  is bash and `sweep.py` is stdlib-only Python; the precedence ladder is small,
  so `resolve_model_tier` reimplements it rather than shelling out. A unit test
  pins the two implementations to the same behavior.
- **No `min_governance_kit` bump.** The directives still call the pre-existing
  `subagent_attest`; the new tier/isolation resolution is internal to `lib.sh`,
  and an older runtime simply ignores the `defaults.conf` (graceful degradation
  — the knobs don't take effect, behavior is unchanged), matching the #325
  precedent.
