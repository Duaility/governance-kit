# issue-327: sync dogfood to kit 0.11.0, audit 0.7.0, foundation 0.5.1, commits 0.2.2

Post-release dogfood sync. Moves this repo's own `.governance/` consumer tree
from the previous release (kit 0.10.2 / audit 0.6.1 / foundation 0.5.0 / commits
0.2.1) to the freshly cut `kit/v0.11.0`, `audit/v0.7.0`, `foundation/v0.5.1`, and
`commits/v0.2.2` tags — entirely through the released/pinned kit's verbs
(`kitverb.py` / `packverb.py`), no hand-edits to the lockfile, the manifest, or
the consumed directive bodies. The one hand action is `git rm`-ing the seven
stale `agent-steering-accounting` files the `pack-apply add` re-pin does not
garbage-collect (see `## Decisions`).

## Decisions

- Landed the kit re-sync and the three pack re-pins in a single commit — the same
  shape as prior dogfood-sync commits (#287, #297, #313). The change is a coherent
  "catch up to the last release" unit and reviewing it as one diff is the intended
  consumer experience.
- Re-pinned audit, foundation, and commits with `pack-apply add ...@<tag> --force`
  rather than `pack update`: each pack is pinned at an immutable tag, so `pack
  update` re-resolves the *same* tag (no move). The `--force` is over the
  `kit-apply` changes already staged for this same commit, which are intentional —
  not unrelated drift. For commits, `--decisions skip` held back the two strict-only
  directives (`no-orphan-todos`, `no-unjustified-suppressions`) so the re-pin
  preserves the dogfood's `standard`-preset directive set.
- **`git rm`-ed seven stale `agent-steering-accounting` files** the re-pin engine
  does not garbage-collect: `defaults.conf`, `hooks/pre-commit.sh`, `lib/argv.py`,
  `lib/classifier.py`, `lib/conf.py`, `lib/extract.py`, and `runtimes/claude-code.sh`.
  `pack-apply add` overwrites the files a directive version ships but never deletes
  files that version dropped, so the consumed tree kept the old in-hook-classifier
  artifacts; `consumed-tree-integrity` correctly flagged each as "vendored tree has
  X, which the pin does not materialize" until removed. This is the same orphan-GC
  gap prior dogfood-syncs hit on renamed/removed directive files.
- In-body `governance: allow-toolchain-config` waiver: the kit update regenerated the
  managed `.githooks/*` dispatchers and `.github/workflows/governance.yml` with the new
  `kit-version=0.11.0` marker — the same legitimate toolchain churn the prior
  dogfood-syncs (#287, #297, #313) waived.
- In-body `governance: allow-doc-integrity CONSTITUTION.md` waiver: this commit
  legitimately rewrites the audit CONSTITUTION subsections (the engine-driven
  upserts), and on macOS the frozen-section grep OOMs on the Evolution Log's huge
  single-line entries — the same waiver the prior dogfood-syncs carried.
