## What changed

- `git mv governance/assets/packs/core/ packs/core/` so the kit's own core pack lives at the monorepo root, fetchable as `gh:duaility/governance-kit/packs/core@<rev>`. Renamed in one git operation (history preserved). The kit's lib/ helpers — `install.sh`, `packs.sh`, `hooks.sh`, `packctl.py`, `packverb.py`, `eval-lib.sh`, `working_tree.py` — stay under `governance/assets/packs/lib/` because they're shipped as the skill bundle, not as pack content. Only `packs/core/` (the directives + pack manifest) moves out.
- Drop `builtin` from `packverb.PACK_SOURCES`, the `cmd_lock_add` validation branch, and the legacy comment in `cmd_lock_list`. `governance/assets/packs/lib/packverb.py`: `PACK_SOURCES = {"gh", "local"}` (was `{"builtin", "gh", "local"}`), the `if args.source in {"builtin", "local"} and (args.ref or args.sha)` branch in `cmd_lock_add` collapses to `if args.source == "local" ...`, and the `cmd_lock_list` comment that read "builtin/local packs have no ref/sha" now reads just "local packs". `argparse`'s `choices=sorted(PACK_SOURCES)` automatically rejects `--source builtin` with `invalid choice`, so a legacy install script surfaces the retirement immediately rather than landing a half-formed lockfile entry.
- Update this repo's `.governance/packs.lock` so `governance-kit/core` is recorded with `source: gh` (ref `gh:duaility/governance-kit/packs/core@v0.2`, current HEAD sha pin, subpath `packs/core`) instead of the retired `source: builtin`. The new entry carries `ref`, `sha` (b33ec7a, this branch's phase 1 head), `subpath: packs/core`, `min_governance_kit: ''`, and `installed_at: 2026-05-08T13:00:00Z` — matching what `lock-add --source gh` would emit. The working-tree resolver (#115) short-circuits this lookup during dogfood: `pack add gh:duaility/governance-kit/packs/core` reads from the working tree at `packs/core/` instead of cloning, so the in-repo edit loop stays instant.
- Update flow docs (`INIT_FLOW.md`, `RESET_FLOW.md`, `PACK_VERBS.md`, `LOCK_SCHEMA.md`) so the example payloads, source-discriminator tables, and `lock-add` help reflect the gh-only model. `INIT_FLOW.md`: the bundled-core path reference at line 15 now points at `packs/core/` (with the gh URL annotation), and the Step 8 `lock-add` example at line 171 fetches the kit version's SHA via `packverb fetch` and records the entry with `--source gh --ref ... --sha ... --subpath packs/core` instead of `--source builtin`. `RESET_FLOW.md`: the `--all` row in the scope table (line 87) drops `builtin` from the source-set, and Step 3 (lines 102+) collapses the two-case `builtin`-vs-`gh` resolver into a single `gh` branch that reads `sha` + `ref` + `subpath` from the lockfile. `PACK_VERBS.md`: the "Installed vs local" preamble, the lockfile example, the source-discriminator description, and the `pack remove` guard are all rewritten to describe core as a gh-fetched pack. `LOCK_SCHEMA.md`: the v2 example payload, the source-discriminator table, the field-reference table, and the `lock-add` CLI block all drop the builtin row/column.
- Update tests (`scripts/test-packverb.py`, `scripts/test-packs.sh`, `scripts/test-schema-split.sh`, `scripts/test-packctl.py`, `scripts/test-packctl-validate.py`) so the `--source builtin` cases are replaced with explicit reject-builtin tests + the gh-fetched core pack. `test-packverb.py`: `test_lock_add_builtin_and_local_record_minimal_entry` becomes `test_lock_add_local_records_minimal_entry`, a new `test_lock_add_rejects_retired_builtin_source` asserts the argparse `invalid choice` rejection, the source-validation test no longer exercises builtin's ref/sha rejection (covered by argparse), and `test_lock_list_long_format_emits_source_and_version` records a local row instead of a builtin row. `test-packs.sh`: `PACKS_ROOT` now points at `$ROOT/packs` (the new core location) while a new `KIT_LIB_ROOT` carries the lib/ paths, and the fresh-repo install contract records core with `--source gh` + a fixture sha + subpath. `test-schema-split.sh`: the lockfile-writer test rewrites the core row from builtin to gh (with `--ref`, `--sha`, `--subpath`), the local block extraction is bounded at the next `- id:` marker (so neighboring gh entries don't leak fields into the no-ref/no-sha asserts), and a new assertion confirms `lock-add --source builtin` is rejected. `test-packctl.py` and `test-packctl-validate.py`: the `CORE_PACK = ROOT / "governance" / "assets" / "packs" / "core"` constants both flip to `ROOT / "packs" / "core"`. `test-packverb.py`'s `validate-pack` smoke test hits the same new path.
- Update each directive eval script's ROOT ascent and PACK_DIR for the new path, and add a defensive guard so eval-lib.sh source failures abort the script instead of silently leaking `git commit` calls into the host repo. Each `packs/core/directives/<id>/evals/test.sh` had its ROOT ascent shortened from seven `../` segments (computed for the old `governance/assets/packs/core/...` location) to five (computed for the new `packs/core/...` location), and `PACK_DIR="$ROOT/governance/assets/packs/core"` updated to `PACK_DIR="$ROOT/packs/core"`. A new guard line, `[[ -f "$ROOT/governance/assets/packs/lib/eval-lib.sh" ]] || { echo "eval: ROOT misresolved to $ROOT — refusing to run with broken eval-lib.sh path" >&2; exit 1; }`, sits before the `source` line — without it, an off-by-one in the ascent count silently fails the source, leaves `fixture_init` undefined, and lets subsequent `git commit` calls run with cwd = host repo (which is exactly how 30+ chore commits leaked into this branch's reflog during the first phase 2 attempt before being hard-reset out). The guard converts that class of bug into a clear error.
