# issue-297: sync dogfood to kit 0.10.1 + audit 0.6.0

Post-release dogfood sync, tracked under the release umbrella #295. Moves this
repo's own `.governance/` consumer tree from the previous release (kit 0.10.0 /
audit 0.5.0) to the freshly cut `kit/v0.10.1` and `audit/v0.6.0` tags, entirely
through the released/pinned kit's verbs — no hand-edits to the lockfile, the
manifest, or the consumed directive bodies. The one hand action is deleting four
orphaned files the re-pin engine does not garbage-collect (see `## Decisions`).

## Checklist

- [x] kit re-pinned to 0.10.1 and managed runtime files re-synced
- [x] audit re-pinned to 0.6.0
- [x] orphaned trailer files removed
- [x] suite green after the sync

## Decisions

- Landed the kit re-sync and the audit re-pin in a single commit — the same shape
  as prior dogfood-sync commits (#287). The change is a coherent "catch up to the
  last release" unit and reviewing it as one diff is the intended consumer
  experience.
- Re-pinned audit with `pack-apply add ...@audit/v0.6.0 --force` rather than
  `pack update`: the pack is pinned at an immutable tag, so `pack update`
  re-resolves the *same* tag (no move). The `--force` is over the `kit-apply`
  changes already staged for this same commit, which are intentional — not
  unrelated drift.
- **Hand-deleted four orphaned files** (`prepare-commit-msg.sh` ×2,
  `trailers.py` ×2). This is not a hand-edit of directive *content* — those files
  are not part of the `audit/v0.6.0` pin at all; #293 deleted them upstream and
  `pack-apply` simply does not garbage-collect files a re-pin drops. Deleting them
  makes the consumed tree a true specimen of the pin, which is exactly what
  `consumed-tree-integrity` demands ("remove it or re-pin"). The alternative —
  leaving them — would keep the dogfood enforcing trailer-stamping code the pinned
  release no longer ships.
- In-body `governance: allow-toolchain-config` waiver: the `kit update`
  regenerated the managed `.githooks/*` dispatchers and `.github/workflows/governance.yml`
  with the new `kit-version=0.10.1` marker — the same legitimate toolchain churn the
  prior dogfood-sync (#287) waived.
