## What changed

The agent-governance pack already gates PR existence (`pr-required-when-checklist-complete`). The next link in the canonical `human → issue → agent → PR → review ↔ rework → squash+merge` flow — the review step — had no mechanical gate. This commit adds a sibling directive that turns "self-reviewed" into an invariant: every PR opened from a complete-checklist receipt must carry a codex-authored review before the agent considers the issue done. The directive is local-only because codex is part of the local agent loop, not a merge-gate.

- **Pack directive scaffolded at `extensions/packs/agent-governance/directives/pr-review-required-when-checklist-complete/` with directive.yaml, check.sh, constitution.md, evals/test.sh.** New self-contained directive folder following the kit's standard four-file shape. `directive.yaml` declares `category: AgentDiscipline`, `recommended: true`, `surface: repo-state`, `hook: post-commit`. `check.sh` runs the same trigger as `pr-required-when-checklist-complete` (HEAD has a `receipts/*.md` with at least one `- [x]` and zero `- [ ]` on a non-main branch), then layers the new precondition-skip logic and review-existence check on top. `constitution.md` carries Directive / Rationale / Agent contract / Enforced by / Exceptions sections. `evals/test.sh` mocks `gh` via a PATH shim with three command paths (auth status, pr list, pr view) and seven environment knobs (`MOCK_GH_AUTH`, `MOCK_GH_PR_NUMBER`, `MOCK_GH_REVIEW_COUNT`, `MOCK_GH_LIST_FAIL`, `MOCK_GH_VIEW_FAIL`, plus `CI` for the local-only skip case).
- **Dogfood directive mirrored to `tests/governance/directives/pr-review-required-when-checklist-complete/` with check.sh, constitution.md, directive.yaml.** Three-file dogfood install matching how `pr-required-when-checklist-complete` is laid out (no `evals/` in the dogfood — those live with the pack). Pack ↔ dogfood dual edit is a project invariant; landing only the pack would leave the dogfood missing the directive that the pack ships.
- **Directive is local-only — skips entirely when `CI` is set in the environment.** check.sh's first conditional after `directive_start` / `require_git` is `[[ -n "${CI:-}" ]]` → `printf "⊘ ... (CI environment — directive is local-only)"` and `exit 0`. Codex review is part of the agent's local loop, not a merge gate. The hard merge-gate in CI remains `pr-required-when-checklist-complete` (PR must exist); review quality is verified by humans on the PR.
- **Precondition-skip when no PR exists — defers messaging to `pr-required-when-checklist-complete`.** After the trigger condition matches and `gh` availability is confirmed, check.sh queries `gh pr list --head <branch> --state open --json number --jq '.[0].number // ""'`. Empty result → `printf "⊘ ... (no PR for branch yet — deferring to pr-required-when-checklist-complete)"` and `exit 0`. The cascade falls out of re-evaluation: agent runs `gh pr create`, re-runs `bash tests/governance/run.sh`, this gate now fires and instructs the codex review step. There is no declared dependency between the two directives; each reads its own preconditions on every firing.
- **Invariant: open PR carries a codex-authored review (Pull Request Review whose body contains `<!-- codex-review -->`).** When the precondition holds (PR exists), check.sh queries `gh pr view <N> --json reviews --jq '[.reviews[] | select((.body // "") | contains("<!-- codex-review -->"))] | length'`. Count of zero → violation with an imperative agent contract: `Execute: codex exec 'review PR #<N> and start the review body with <!-- codex-review --> so the governance gate can detect it'`. The marker lets the gate distinguish codex-authored reviews from human reviews — humans don't need this gate's encouragement, and the marker is cheap for codex to emit.
- **Pack eval covers 11 cases.** `evals/test.sh` exercises every branch: no-head (no commits), ci-env-skip (CI=1 short-circuits), no-receipts (no `receipts/` dir), unchecked-remaining (receipt with `- [ ]` items), no-pr-defer (completed receipt + empty `MOCK_GH_PR_NUMBER` → exit 0), review-present (PR exists + `MOCK_GH_REVIEW_COUNT=1` → pass), no-review (PR exists + count 0 → fail), gh-view-error (`MOCK_GH_VIEW_FAIL=1` → fail), gh-list-error (`MOCK_GH_LIST_FAIL=1` → fail), gh-not-authed (`MOCK_GH_AUTH=fail` → skip-with-warning, exit 0), main-branch-noop (on main → exit 0 regardless). All eleven assertions green.
- **Added to `standard` preset in `extensions/packs/agent-governance/pack.yaml`.** Not `minimal` — `minimal` covers receipt + commit-issue match + PR existence, which any agent-governed repo needs. The codex review gate is more opinionated (assumes codex CLI is the agent runtime), so it joins issue-templates / issues-tracked / agent-token-accounting in the standard preset that signals "full chain".
- **DIRECTIVES_CATALOG.md gains a new directive row and updated preset table.** Inserted under the `agent-governance` table directly after `pr-required-when-checklist-complete`, with prose covering the trigger, the precondition-skip composition pattern, the local-only behavior, and the gh skip-with-warning fallback. Preset table updated so `standard` row shows the new directive after `agent-token-accounting`.
- **Top-level README.md community-pack table gains a row for the new directive.** Inserted after the `pr-required-when-checklist-complete` row, with the marker `<!-- codex-review -->` called out so readers see the concrete shape, and the `Local-only` flag bolded so the CI-skip behavior is unambiguous.
- **agent-governance README.md auxiliary-directives section + presets table updated.** "Two directives" → "Three directives". New bullet introduces the review-gate, names the precondition-skip composition, and flags the local-only skip in CI. Preset table's `standard` row gains the directive; cumulative count goes 6 → 7 across `standard` and `strict`.
- **Top-level README.md gains a "Composition" subsection explaining level-triggered reconciliation with kubectl / Make / systemd analogies.** New subsection between "Anatomy of a directive" and "Core pack" — captures the design stance discussed during scoping: directives are invariants on state, the runner sorts directives alphabetically with no `depends_on:` / `order:` machinery, dependent directives encode their own preconditions and skip-with-info when not met, and the agent's loop is "take the mandated action, then re-run governance to surface the next gap" — the same shape as `kubectl apply`, Make prerequisites, and systemd `ConditionPathExists=`.
- **Post-commit dispatcher banner upgraded from soft `⚠ advisory` framing to a loud `✗ POST-COMMIT GOVERNANCE FAILED` block addressed at agent readers.** The cascade design (precondition-skip + agent re-runs governance after each mandated action) only converges if the agent actually re-engages after `git commit`. With the previous `⚠ Post-commit advisory` wording the bash-tool exit code was 0 and the framing read as a warning, so agents tended to treat the commit as "done" and never trigger the next iteration. The new banner uses heavy `═` box drawing, `✗ FAILED` glyphs, direct `Agent reader:` addressing, names the convergence command (`bash tests/governance/run.sh`) explicitly, and reuses the "durable authorization — do not re-pose as a question" language already in the create-gate and review-gate violation messages. Drops the misleading "CI will enforce these on push" line because the new review-gate is local-only — a blanket CI-backstop claim no longer holds across all post-commit directives.
- **Banner explicitly acknowledges that git ignores post-commit hook exit codes by design, closing the "exit 0 = success" rationalization gap for agent readers.** The banner body includes a sentence — "git ignores post-commit hook exit codes by design, so this shell returned 0 even though governance failed. This is NOT a successful command." — that names the underlying mechanism agents would otherwise use to dismiss the violation. Without this acknowledgement, an agent observing exit 0 in its tool result has a strong prior that the operation succeeded and the stderr output is informational; with the acknowledgement, the agent has the framing it needs to override that prior and treat the violation as a mandated next step.
- **Generator template at `governance/assets/packs/lib/hooks.sh` and dogfood-installed `.githooks/post-commit` updated in lockstep.** Both files carry the same banner and the same updated header-comment block describing the new posture. Header comments now read: "Post-commit cannot block — `git commit` has already succeeded and git ignores this hook's exit code by design. Violations are surfaced as a loud 'POST-COMMIT GOVERNANCE FAILED' banner addressed at agent readers, compensating for the missing exit-code signal." Future re-installs via `governance init` will emit the new framing; existing repos that already installed the older version will see the new framing on next `governance pack update`.

## Out of scope

- **CONSTITUTION.md amendment.** Per AGENTS.md, hand-editing `CONSTITUTION.md` is not supported — the canonical landing path is the governance skill's `directive` / `pack` verbs which keep the directive section + Evolution Log entry in lockstep. This commit lands the pack + dogfood + docs; the constitution amendment is a separate concern that the maintainer can land via the proper verbs.
- **`governance.yml` adjustment to re-fire on `issue_comment`.** Discussed during scoping as a way to close the "codex posts review comment but CI doesn't auto-rerun" gap — left out because the directive is local-only by design (codex review is part of the local loop, not a merge gate). If the directive is ever promoted to CI-hard-gate in a future iteration, the workflow trigger expansion can land then.
- **Configurable review marker.** check.sh hard-codes `<!-- codex-review -->`. A future iteration could read a marker token from `tests/governance/review.conf` (or directive.yaml) so other agent runtimes (Claude Code, Cursor) can plug in with their own marker. Not in scope here — the user explicitly named codex CLI based PR reviews as the target.
- **Replacing `gh pr create` with a codex-driven create-and-review flow.** Discussed during scoping as a possible third interpretation of the request; rejected in favor of keeping the existing `pr-required-when-checklist-complete` create-gate single-purpose and adding the review-gate as a sibling.
