# issue-192 — Decompose core into concern-scoped packs with qualified directive identity

Decomposes the bundled `governance-kit/core` catch-all into five concern-scoped packs, splits `workflows-hardened` into the two OpenSSF Scorecard checks it fused, renames `version-consistency` → `kit-version-sync`, and lands the qualified directive-identity model (homonyms, pack-qualified conf overlays, `run.sh` qualified filter).

## What changed

- **Five concern packs replace core.** New pack roots `packs/{foundation,security,docs,commits,audit}/`, each with a `pack.yaml` (v0.1.0) and per-pack `minimal`/`standard`/`strict` blocks; every former core directive was `git mv`'d into exactly one new pack and `packs/core/` was removed. Each moved directive's `evals/test.sh` (`PACK_DIR`, `CHECK`) and `constitution.md` `Enforced by` path were repointed to the new pack. The five packs exist under `packs/`.
- **Grouping by concern.** `foundation` (repo baseline — required docs, kit-version coherence, working-tree `repo-hygiene`), `security` (supply-chain + credentials), `docs` (doc-graph health), `commits` (commit-message + in-source-marker discipline), and `audit` — a single coherent concern, *a trustworthy record of agent work*: issue → receipt → commit **traceability** (`issue-templates`, `issues-tracked`, `receipt-per-issue`, `commit-issue-receipt-match`), cost + steering **accounting** (`agent-token-accounting`, `agent-steering-accounting`), and the record **integrity** that keeps them tamper-proof (`doc-integrity`, `toolchain-config-protection`). No single-directive packs; `repo-hygiene` rides in `foundation`'s `minimal`. Preset homes preserved across all moves — the union is unchanged.
- **Security split — the reference cut.** `workflows-hardened` is retired and split into `token-permissions` (workflows declare a least-privilege `permissions:` block — `standards: ["OpenSSF Scorecard: Token-Permissions"]`) and `pinned-dependencies` (third-party actions pinned to a full commit SHA — `standards: ["OpenSSF Scorecard: Pinned-Dependencies"]`), each a new directive folder with check/constitution/directive.yaml/evals and per-occurrence waivers. `secrets-hygiene` moved unchanged; its `no-secrets` sub-check is renamed `hardcoded-credentials` (CWE-798) and it carries `standards: ["CWE-798"]`. DIRECTIVES_CATALOG.md gained a Standards column rendering this metadata.
- **`version-consistency` → `kit-version-sync`.** The folder, `directive_start` arg, `constitution.md` heading + Enforced-by path (now `governance-kit/foundation`), eval `EVAL_ID`, the `allow-version-consistency` → `allow-kit-version-sync` waiver token, and README/VERSIONING/INSTALL_SCHEMA/RELEASE_FLOW references were all renamed; an Evolution Log entry records it. It rides into `foundation` and stays distinct from this repo's local `kit-version-consistency` dogfood directive.
- **Preset union equals the old sets.** Each pack declares only the tiers it contributes to; `packctl union-preset` across the five reproduces today's `minimal`/`standard`/`strict` exactly (with `workflows-hardened` → `token-permissions` + `pinned-dependencies`, `version-consistency` → `kit-version-sync`). `scripts/test-packs.sh`'s fresh-repo contract now installs the unioned `standard` preset across all five packs.
- **`always_install` reservation widened.** `packctl.py` now reserves `always_install: true` to the `governance-kit/*` bundled packs (was `governance-kit/core`), so `repo-hygiene` (foundation), `doc-integrity` (audit), and `agent-steering-accounting` (audit) keep mandatory status in their new homes; the reservation is enforced for `governance-kit/*` only.
- **Cross-pack duplicate short id → notice.** `validate_pack_set` downgrades a cross-pack duplicate directive id from a hard error to an informational notice on stderr (exit 0), since homonyms coexist and both run; suppression remains explicit via `replaces:`.
- **Pack-qualified conf overlays.** `conf_file` (lib.sh, both copies) derives `<owner>/<pack>` from the running `check.sh`'s `$0` and resolves `.governance/conf/<owner>/<pack>/<id>.conf`; the agent-steering `lib/conf.py` and agent-token `lib/rates.py` derive the same from `__file__`; `install.sh` `seed_directive_conf`, `initapply.py`, `packplan.py`, and `packapply.py` write/read/prune the qualified path. The eval harness exports a qualified `$EVAL_CONF`; the dogfood has no overlays to migrate (none existed).
- **CONSTITUTION grouped by pack.** The `## Directives` body is regrouped under per-pack `## <owner>/<pack>` headings (directives stay `### <id>` so docsurgery still resolves them); an Evolution Log entry was appended (the frozen section is otherwise untouched).
- **`run.sh` qualified filter.** `run.sh <bare-id>` runs every homonym; `run.sh <owner>/<pack>/<id>` runs exactly one (both copies updated).
- **Dogfood reshaped.** The committed consumed tree moved to `.governance/packs/governance-kit/<pack>/directives/<id>/`; `.governance/packs.lock` rewritten to five pack entries; the local `kit-version-consistency` floor check generalized from `packs/core` to every `packs/<pack>`; immutable ledgers (`receipts/`, `plans/`) are now excluded from the internal-doc-link check so the `packs/core` move doesn't break unfixable links in frozen records.
- **Tests + docs.** Unit tests that pinned `packs/core` / the old `always_install` message / the hard-error duplicate were repointed to bundled packs and the new behaviour; README, AGENTS, ARCHITECTURE, INIT_FLOW, VERSIONING, RELEASE_FLOW, INSTALL_SCHEMA, PACK_AUTHORING (identity model + `standards:` field), `release.yml`, and `governance/evals/init/evals.json` updated.
- **Per-pack release axes (lazy tagging).** `scripts/release.sh`'s axis argument generalizes from `kit|core` to `kit|<pack-name>` (validated against `packs/<name>/pack.yaml`; the retired `core` axis now errors). A pack release bumps only `packs/<pack>/pack.yaml` and cuts a `<pack>/vX.Y.Z` tag; the changelog generator is **path-scoped** (`-- packs/<pack>` for a pack, `-- . :(exclude)packs` for the kit) so each axis's changelog lists only its own subtree's commits. `release.yml`'s tag trigger collapses `kit/v*` + `core/v*` into one future-proof `'*/v*'` pattern (covers kit, every pack, and legacy `core`). Tagging is **lazy** — one `release.sh` invocation per pack whose subtree actually changed, à la Go-modules / Changesets, not a flat bump across all five. VERSIONING.md, RELEASE_FLOW.md, README, AGENTS, and the CHANGELOG header document the per-pack scheme and mark `core` historical. Verified by `--dry-run` across `kit`, a pack, the retired `core`, and a bogus axis.

## Out of scope

- New security directives (dangerous-workflows, dockerfile-hardening, SBOM, vuln-floor, branch-protection) — the roadmap the Standards column exposes as gaps.
- First releases/tags of the new packs — actually cutting `<pack>/v0.1.0` for the five packs and repinning the dogfood lock from `@main` to those tags is a post-merge runtime action, not part of this PR. (The `release.sh` *tooling* for per-pack axes is now in scope — see What changed.)
- The qualified waiver form (`allow-<owner>/<pack>/<id>`) — deferred until a real homonym exists; waiver tokens stay flat.
- Any profile mechanism beyond `union_preset`; grouping the init-assembled consumer constitution by pack (the dogfood CONSTITUTION is grouped; `initapply` assembly is unchanged).
- Renaming the local dogfood `kit-version-consistency`.

## Decisions

- **Dogfood installed-directive set held constant.** The consumed tree was *reshaped* into the new pack layout keeping its existing installed set (the frozen 0.4.0 directives), applying only the issue-mandated transforms (`version-consistency` → `kit-version-sync`; `workflows-hardened` → `token-permissions` + `pinned-dependencies`). It was not *expanded* to the current source set (e.g. `toolchain-config-protection`, `internal-doc-links` rename) — that is a pack-update/repin concern, separate from this structural reshape, and the consumed tree deliberately lags its lock pin per the existing convention.
- **Frozen records excluded from the link check, not edited.** Moving `packs/core` broke a markdown link in a frozen receipt (issue-134) that doc-integrity forbids editing. Rather than waive or edit an immutable record, `receipts/` and `plans/` are now excluded from `internal-doc-links` / `no-broken-internal-doc-links` — their links describe a past state and can't be repaired without violating append-only. Active docs (VERSIONING.md) with the same broken link were fixed normally.
- **Conf qualifier derived from `$0`, with a bare fallback.** `conf_file` derives `<owner>/<pack>` from the running check's path (reliable in both `run.sh` and hook contexts, absolute or relative). When the caller is not an installed check (direct-invocation unit tests), it falls back to the bare path — this keeps `test-runtime.sh`'s direct helper calls green while every installed directive gets the qualified overlay.
- **Local `kit-version-consistency` floor check generalized.** Its `packs/core/pack.yaml` reference would have silently no-op'd after the reshape; it now validates every `packs/<pack>/pack.yaml` floor, which is a strict improvement, not a rename (the rename is out of scope).
- **`validate_pack_set` duplicate downgrade is forward-looking.** The five bundled packs have unique ids, so the notice path doesn't fire today; it exists for community-pack homonyms surfaced by `governance pack add`. `init`'s own `collisions()` refusal is unchanged (it only fires on the same selected pack-set, which the bundled packs never trigger).
- **Lazy per-pack tags over a single bundle tag.** The shortlist was (a) lockstep — one shared version + tag for all packs (Babel/Angular), (b) one bundle tag with independent in-tree versions, and (c) per-pack tags cut lazily (Go-modules/Changesets). (b) was tempting for low ceremony but is really only standard for **registry-published** monorepos, where the git tag is an incidental marker and consumers resolve versions from npm/cargo/PyPI. governance-kit has no registry — consumers pin by **git ref** (`gh:…/packs/<pack>@<tag>`), so the tag *is* the distribution mechanism, and the fitting precedent (Go multi-module) mandates per-unit tags. (c) keeps the per-pack semver the decomposition exists to provide, and the feared "a tag for every pack every release" cost is illusory: you tag only the pack(s) that changed, so a typical PR cuts one or two — the all-packs-at-once moment is a one-time bootstrap.
- **Release tooling folded into this PR though #192 deferred it.** #192 listed "release.sh extension for per-pack tag axes" as out of scope. It was pulled in here (user decision) because the new packs need a working release path, and authoring it against the live multi-pack tree keeps the tag scheme, `release.yml` trigger, and the eventual lock-repin one coherent story rather than a structure that ships with no way to version its parts. Actually cutting the `v0.1.0` tags and repinning the lock stays out of scope — that is a post-merge runtime action.
- **The concern-balanced split landed in this PR, not a follow-up — deviation from the issue's literally-named packs.** Issue #192 named the seven packs as `{foundation,security,docs,commits,hygiene,audit,integrity}`. Mid-review, the lopsided distribution (audit=6, hygiene=1) was reworked into `{…,process,audit,…}` with `repo-hygiene` in `foundation`. It was folded into this PR rather than deferred because moving a directive between packs changes its identity (`governance-kit/audit/receipt-per-issue` → `governance-kit/process/receipt-per-issue`); pre-release that is free, but once the packs are tagged the same move is an identity-breaking MAJOR on two packs. Since the decomposition had not yet shipped, fixing the boundaries before they became history avoided a double reshape and a post-release break. The kit is V0, so amending the issue's named set is in-policy.
- **Collapsed 7 → 5: fewer packs over smaller packs.** The pack count itself was then judged too high. The seven-pack cut had optimized for *small, single-purpose* packs (flat 2–4 directives each); the maintainer preferred *fewer* packs even at the cost of bigger ones. The two pulls are genuinely opposed — you cannot have both — so this is a deliberate priority flip. The collapse is principled, not arbitrary: the three packs that were all facets of one concern — `process` (creates the records: issues/receipts), `audit` (stamps them: cost/steering), `integrity` (protects them: append-only / anti-gaming) — merge into a single `audit` pack = *a trustworthy record of agent work*. `foundation`, `security`, `docs`, `commits` stay clean single concerns. This fully reverses the `process`/`audit` split from the rebalance above (a transient intermediate state, never shipped); `repo-hygiene` stays in `foundation`. `audit` is now the only large pack (8 directives) but it is genuinely one concern, not a grab-bag. Free pre-merge for the same identity reason as the rebalance; the squash-merge collapses the intermediate create-then-dissolve of `process`/`integrity` into one clean diff vs main.
