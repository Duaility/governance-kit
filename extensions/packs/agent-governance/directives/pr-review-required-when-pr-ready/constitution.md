### pr-review-required-when-pr-ready

- **Directive**: When the current branch is not `main` / `master` AND has an open pull request on the GitHub remote that is **not in draft state** (i.e., marked ready for review), that PR must carry a codex-authored review — a Pull Request Review whose body contains the marker `<!-- codex-review -->`. The directive runs from the `post-commit` hook locally and is **skipped entirely in CI** (when `CI` is set in the environment); codex is part of the local agent loop, not a merge-gate.
- **Rationale**: "Receipt checklist complete" and "PR ready for review" are different signals. The agent may finish the checklist, push, and keep iterating in draft (rerunning CI, polishing, taking another pass). Tying the review-mandate to checklist completion fires `codex exec` the moment the last `[ ]` is ticked — even if the author isn't done — and re-fires noisily after every rework commit while the checklist stays green. The right axis is GitHub's first-class draft → ready transition (`gh pr ready`): the agent (or a human) explicitly marks the PR ready, and *that* gesture is the durable authorization for the review-mandate to fire. Composition with `pr-required-when-checklist-complete` is by separation of axes — that directive demands a PR exists once the checklist completes (draft is fine); this one demands a codex review once the PR is marked ready. Each reads its own precondition; the loop converges via level-triggered reconciliation.
- **Agent contract**: When this directive fires under an agent runtime, the agent's next action is to execute `codex exec "review PR #<N> and start the review body with <!-- codex-review -->"`. This is **not** a question to pose to the user. The directive's firing is the durable authorization. After codex posts the review, re-run `bash tests/governance/run.sh` to confirm; level-triggered convergence handles the rest.
- **Enforced by**: `tests/governance/directives/pr-review-required-when-pr-ready/check.sh`. Local enforcement is **advisory** (post-commit cannot block); the directive does not run in CI.
- **Exceptions**: Skip-with-info when no open PR exists for the branch (the directive does not apply — readiness has no signal to read). Skip-with-info when the PR is in draft (mark ready with `gh pr ready <N>` to request review). Skip-with-warning when the GitHub CLI (`gh`) is not installed or not authenticated. Skipped entirely when `CI` is set in the environment. The directive is also a no-op on `main` / `master` and when no commits exist yet. When `gh` is present but the API call fails, the directive fails (network or API issues should not silently bypass the gate).
