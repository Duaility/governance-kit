### agent-steering-accounting

- **Directive**: For every commit produced through a recognised agent runtime, detected human-steering events on this branch since the last commit are recorded as append-only rows in `STEERING.md`, and each row's `steer-key` is mirrored as a repeated `Steer-Key:` trailer on the commit message. Commits with at least one event additionally carry three summary trailers — `Steer-Count: <N>` (must equal the number of `Steer-Key:` trailers), `Steer-Types: <type>=<N>,...` (sorted, must agree with the matched rows' `type` columns), and `Steer-Tiers: <tier>=<N>,...` (sorted, must agree with the matched rows' `tier` columns). A row exists for every `Steer-Key:` trailer; a `Steer-Key:` trailer exists for every row whose key carries this commit's prefix. `STEERING.md` rows are well-formed — 9 columns (`steer-key | session | issue | type | tier | tool | proposed | user-reason | commit`), `type` is one of `tool-denial`/`interrupt`/`correction`, `tier` is one of `structural`/`classifier`/`lexical`, and `steer-key` is unique within the file. Row order is monotonically non-decreasing in the embedded epoch — append-only, never reordered. A commit with zero detected events carries none of the four trailers and the directive is satisfied.
- **Rationale**: Token-accounting captures *machine* cost. Steering-accounting captures *human* steering cost — the moments where the operator denied a tool call, interrupted a turn, or redirected the agent. These events are the highest-signal record of where the agent's instructions or directives are misaligned with intent, and today they're invisible: the commit history shows the result of a redirect, never the redirect itself. A durable ledger plus stamped trailers turns each steering event into a citable record that survives squash merges. Two-tier detection: tier 1 (structural — denials and interrupts) reads runtime sentinels with near-zero false positives; tier 2 (corrections) shells out to the active runtime's headless CLI for semantic classification, falling back to a regex pre-filter only when the CLI is unreachable. The runtime CLI is by definition installed in any session that wrote the transcript, so it's a free dependency. Privacy is the directive's single load-bearing tradeoff: `user-reason` is committed verbatim, so the directive is opt-in only, never in any preset, and explicitly flagged for public-repo operators.
- **Enforced by**: `tests/governance/directives/agent-steering-accounting/check.sh`, plus sibling helpers in the agent-steering-accounting directive folder — `hooks/pre-commit.sh` extracts events from the active session JSONL (via `runtimes/<runtime>.sh`), appends rows, and writes a handoff file; `hooks/prepare-commit-msg.sh` reads the handoff and stamps matching `Steer-Key:` trailers. `lib/extract.py` houses the two-tier detection, `lib/ledger.py` the row I/O, `lib/trailers.py` the trailer parser. The bootstrap hook generator wires the three hooks into `.githooks/pre-commit`, `.githooks/commit-msg`, and `.githooks/prepare-commit-msg`.
- **Exceptions**: Merge commits and revert commits are exempt (merges detected via `git log --format=%P` showing >1 parent, reverts via subject starting with `Revert "`). Commits authored outside a recognised agent runtime (no session JSONL discoverable) are exempt — the directive is silent, not a blocker, when there is no transcript to read. `SKIP_GOVERNANCE=1 git commit ...` and `git commit --no-verify` skip the local hooks; CI re-enforces row/trailer cross-checks.

> **Privacy note.** `user-reason` cells preserve the verbatim text the operator typed in a deny dialog or correction. That text becomes part of the repo's public history. Do not enable this directive on a public repo without thinking through what those messages could leak. The lexical tier (correction-pattern matching on user messages) is gated behind `STEERING_LEXICAL=1` precisely because correction text is more likely to contain incidental context than a typed deny-reason.

> **Installation note.** The directive folder is self-contained — `lib/` (extract, ledger, trailers), `hooks/` (pre-commit extractor + prepare-commit-msg stamping), and `runtimes/` (per-runtime transcript readers) all live inside the directive folder and are installed as a unit. See `governance/references/AGENT_STEERING_ACCOUNTING.md` for runtime wiring and the extractor's two-tier model.
