### pr-required-when-checklist-complete

- **Directive**: When HEAD carries a tracked `receipts/*.md` whose `## Checklist` section has at least one `- [x]` item and zero `- [ ]` items (i.e. the work is fully done by the agent's own attestation), and the current branch is not `main` / `master`, an open pull request must exist for the current branch on the GitHub remote. The directive runs from the `post-commit` hook locally — it reads HEAD content directly (the just-completed commit) and surfaces the violation as an *advisory* (the commit cannot be blocked at that point; CI is the hard gate). On CI, the same check fires from `tests/governance/run.sh` and fails the build.
- **Rationale**: The receipt's `## Checklist` (required by `receipt-per-issue`) is the agent's mechanical signal for "I am done." Without a directive that *acts on* that signal, the checklist becomes a self-report no one consumes — the work sits on a feature branch waiting to be noticed. The post-commit firing means the developer gets immediate feedback at the moment the work completes ("checklist is done; PR is now required"), and CI is the backstop that fails the build if the PR still doesn't exist by the time the branch is pushed. The gate is shaped as a check, not an action: governance-kit directives describe invariants on tree state, not side effects on remote systems. The directive only verifies a PR exists; the agent (or developer) opens it. Post-commit is the natural firing moment because the trigger condition (zero `[ ]` items in HEAD's receipt) only becomes true *after* a commit lands.
- **Agent contract**: When this directive fires under an agent runtime, the agent's next action is to execute `gh pr create --fill --base main --head <branch>`. This is **not** a question to pose to the user ("want me to open the PR?"). The directive's firing is the durable authorization — re-posing it as a fresh decision needing approval re-injects the friction the directive was designed to remove. If the agent has a reason it cannot open the PR (network failure, auth issue, branch state ambiguity), it surfaces that reason and the remediation; it does not ask permission to take the mandated action.
- **Enforced by**: `tests/governance/directives/pr-required-when-checklist-complete/check.sh`. Local enforcement is **advisory** (post-commit cannot block); CI enforcement is **hard** (the build fails).
- **Exceptions**: Skip-with-warning when the GitHub CLI (`gh`) is not installed or not authenticated — local developers without `gh` are not blocked, but CI environments (where `gh` is expected) will enforce. When `gh` is present but the `gh pr list` call fails, the directive fails (network or API issues should not silently bypass the gate). The directive is also a no-op on `main` / `master` and when no commits exist yet.
