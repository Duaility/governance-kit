### pr-review-required-when-checklist-complete

- **Directive**: When HEAD carries a tracked `receipts/*.md` whose `## Checklist` section has at least one `- [x]` item and zero `- [ ]` items, the current branch is not `main` / `master`, and an open pull request exists for the current branch on the GitHub remote, that PR must carry a codex-authored review — i.e. a Pull Request Review whose body contains the marker `<!-- codex-review -->`. The directive runs from the `post-commit` hook locally and is **skipped entirely in CI** (when `CI` is set in the environment); codex is part of the local agent loop, not a merge-gate. When no PR exists for the branch yet, the directive skips-with-info and defers messaging to `pr-required-when-checklist-complete`.
- **Rationale**: The canonical agent flow is `human → issue → agent → PR → review ↔ rework → squash+merge`. Once the agent produces a complete-checklist receipt and opens a PR, the next mandated step is a review. Wiring `codex exec "review PR #N"` into a directive turns "self-reviewed" from a polite suggestion into an idempotent invariant: every PR opened from a complete-checklist receipt carries a codex review before the agent can consider the issue done. The `<!-- codex-review -->` marker lets the gate distinguish codex-authored reviews from human reviews — humans don't need this gate's encouragement, and the marker is cheap for codex to emit. Composition with `pr-required-when-checklist-complete` is via precondition-skip, not declared dependency: this directive checks for a PR first and steps aside if there isn't one, so the create-gate fires alone on the first pass and this gate fires on the next re-evaluation. That is the same level-triggered reconciliation pattern Kubernetes / Make / systemd use — describe state, let each unit check its own preconditions, the loop converges.
- **Agent contract**: When this directive fires under an agent runtime, the agent's next action is to execute `codex exec "review PR #<N> and start the review body with <!-- codex-review -->"`. This is **not** a question to pose to the user. The directive's firing is the durable authorization. After codex posts the review, re-run `bash tests/governance/run.sh` to confirm; level-triggered convergence handles the rest.
- **Enforced by**: `tests/governance/directives/pr-review-required-when-checklist-complete/check.sh`. Local enforcement is **advisory** (post-commit cannot block); the directive does not run in CI.
- **Exceptions**: Skip-with-info when no PR exists for the branch yet (deferred to `pr-required-when-checklist-complete`). Skip-with-warning when the GitHub CLI (`gh`) is not installed or not authenticated. Skipped entirely when `CI` is set in the environment. The directive is also a no-op on `main` / `master` and when no commits exist yet. When `gh` is present but the API call fails, the directive fails (network or API issues should not silently bypass the gate).
