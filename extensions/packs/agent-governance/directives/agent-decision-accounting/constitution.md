### agent-decision-accounting

- **Directive**: Commits that reference load-bearing human decisions carry a `Decision-Key:` trailer listing one-or-more comma-separated keys and a paired `Decision-Diverged: <M>/<N>` counter where `N` equals the number of listed keys and `M` equals the count of listed rows whose `diverged` value is not `agreed`. Every key in the trailer must resolve to exactly one append-only row in `DECISIONS.md` at repo root. `DECISIONS.md` rows are well-formed — 11 columns (`decision-key | agent | session | issue | phase | question | lean | choice | diverged | cost-key | note`) — with `decision-key` unique within the file, `diverged ∈ {agreed, overrode, reframed, deferred}`, `phase ∈ {scoping, plan-review, pr-review, post-merge}`, `agent`/`session`/`issue` non-empty, and `issue` matching `#N`. When `cost-key` is non-empty and `COSTS.md` is present, the referenced row must exist there. Commits without a `Decision-Key:` trailer are not obligated to have a ledger row.
- **Rationale**: A repo that opts into agent-governance throws away a high-value signal every time the human overrides (or reframes) the agent without a durable record. `DECISIONS.md` turns that signal into an append-only ledger keyed on a trailer that survives squash merges, same mechanism as `COSTS.md`. Recording **every load-bearing decision** (not just divergences) is deliberate — an override count without a baseline is uninterpretable; you need both the numerator and the denominator to reason about override rate, reframe rate, or time-to-override. The fixed 4-state divergence vocabulary (`agreed` / `overrode` / `reframed` / `deferred`) is what makes the ledger machinable downstream — a binary "divergence: true/false" flag would collapse the `reframed` case, which is the single most valuable metric because it flags the *agent's question set* as broken rather than its lean accuracy. The optional `cost-key` join lets "how many tokens did this override cost to re-plan" be a single SQL-shaped join away without coupling the two directives.
- **Enforced by**: `tests/governance/directives/agent-decision-accounting/check.sh`, which runs in two modes — Mode A as a `commit-msg` hook validating the pending commit's trailer/ledger relationship, Mode B as a CI walk over `base..HEAD`. Both modes also call the directive's `lib/ledger.py validate` for repo-wide shape checks against `DECISIONS.md`. The directive is runtime-agnostic — unlike `agent-token-accounting` which reads transcripts via per-runtime readers, `DECISIONS.md` rows are agent-authored at question time (the lean must be declared structurally, not inferred post hoc), so the same markdown-row writing convention works identically on Claude Code and Codex with no `runtimes/<name>.sh` sibling needed.
- **Exceptions**: Merge commits and revert commits are exempt (merges detected via `git log --format=%P` showing >1 parent, reverts via subject starting with `Revert "`). Commits that simply did not record any load-bearing decisions are also exempt — the trailer is optional; it is only the *inconsistency* between trailer and ledger that is a violation.

> **Installation note.** The directive folder is self-contained — `lib/` (ledger, trailers) lives inside the directive folder and is installed as a unit. No runtime-specific readers are needed. See `governance/references/AGENT_DECISION_ACCOUNTING.md` for the skill-side question-ask contract, Codex + Claude Code worked examples, and how rows are authored at question time.
